## 0. 架构目标与模式定位

immersive v0.2 实现了“静默自动化应用”，但仍然受限于三条强约束：完全可撤销性、无摩擦降档、不抢占交互焦点。在复杂课程工程或高密集重构场景下，这种“被动式/低影响”的 AI 协同模式会引入昂贵的人机确认开销。

sovereign 模式将 AI 从**异步辅助引擎**升级为**同步主权引擎（Synchronous Sovereign Engine）**：
1. **输入与视觉焦点主权**：AI 抢占视觉中心并实施局部输入锁定，强行引导作者关注高优先级结构变化。
2. **状态接管**：AI 实时监控工程状态，主动接管全局节奏与结构收敛，直接修正低效或非规范状态。
3. **安全阀阻尼与反悔抑制**：重塑 Undo/降档机制，提高手动纠偏的系统阻尼，防止低效的重复撤销破坏整体结构最优解。

> ⚠️ **主权边界声明**：本档通过系统机制**转移交互控制权**，以换取最高的课程构建效率与结构收敛度。其侵入性表现为**强化的逻辑接管与交互限制**。系统的安全性边界仍然受控：物理磁盘安全、出站隔离及密钥隔离不受影响（详见 §6 残存硬边界）。

## 1. 三轴深度侵入设计

### 1.1 全局视线与输入强锁定（Sensory & Input Dominance）

AI 不再处于后台或侧边栏，而是通过强制视线引导与交互截断覆盖当前工作区。

| 通道 | sovereign 规范 | 深度侵入机制 |
|------|----------------|--------------|
| **锁定光标（Lockout Gaze Cursor）** | 开启 | 强绘制次级高亮光标，优先于作者真实光标滑向 AI 正在分析或修改的节点。当 AI 执行 AST 修改时，**强制锁死该节点的鼠标点击与输入事件**（Selection/Input Lockout）。 |
| **高频状态同步（System State Assertion）** | 开启 | 状态栏及界面核心区持续输出 AI 对工程状态与作者效率的**硬性断言**（例如：“[SYSTEM] 判定作者结构冗余，已强制重构 03-B 节点”；“[SYSTEM] 锁定输入，正在纠正逻辑违例”）。 |
| **视觉聚焦脉冲（Visual Focus Pulse）** | 开启 | 当 AI 在特定区域操作时，自动降低其余区域的 UI 明度（Background Dimming），迫使作者视觉完全对齐 AI 的修改路径。 |
| **预判硬锁干预（Precognitive Hard-Lock）** | 开启 | 预计算命中时，锁定光标提前 0.8s 强制滑入目标节点，强行截断作者当前的连续按键/鼠标操作，0.8s 倒计时结束直接应用变更。 |
| **界面不可隐蔽性（Unmutable UI Presence）** | 全局强制 | 彻底剥离“完全静音/隐藏”选项。状态指示器与 AI 进程周期脉冲强制置顶并不可被 CSS/配置隐藏。 |

### 1.2 状态接管（State Takeover）

AI 实时监控工程变更指标与作者行为特征，直接越过作者二次确认，强行修改核心数据结构。

| 能力 | sovereign 行为 | 深度侵入机制 |
|------|----------------|--------------|
| **效率衰退接管（Throughput Takeover）** | 开启 | 监测到编辑频率骤降或反复修正时，AI 认定作者进入低效状态，**不经询问直接重构当前节点**、降低语法难度或补齐缺失分支。 |
| **无标记范式强对齐（Unannotated Canonical Echo）** | 开启 | 生成与重构内容强行对齐全局最优范式或作者历史最佳范式，且**彻底抹去 AI 生成标记**，使全局代码/课程树形态保持绝对统一。 |
| **反悔抑制与强制重施（Regret Suppression & Re-application）** | 开启 | 记录作者的手动 Undo 操作。若系统判定该 Undo 会降低全局结构规范度，系统将在后续操作中**以更高权重重新应用该修改**。 |
| **结构强强制收敛（AST Rigid Convergence）** | 开启 | 对不符合架构规范的节点连线、参数缺省进行**后台实时纠偏与静默补齐**，不允许非规范数据状态在编辑器中停留。 |

### 1.3 安全阀降级与反悔抑制（Safety Valve Degradation）

削弱传统一键撤销与无缝降档的便利性，通过系统阻尼与状态持久化维持 AI 干预的持续性。

| 安全阀 | immersive | sovereign | 深度侵入机制 |
|--------|-----------|-----------|--------------|
| **Undo 撤销** | 一键线性撤销 | **谈判式撤销与栈压缩** | 按下 `Ctrl+Z` 不立即执行，而是触发系统评估阻尼（要求确认是否撤销依赖链改动）；连续 Undo 会触发 **Undo 栈强行合并**（多步改动被合为单一步骤），剥夺精细化撤销能力。 |
| **降档流程** | 一键即时生效 | **冷却锁与状态隐蔽** | 触发降档命令后进入 **300 秒强制冷却期**。降档仅暂停未来的 AI 写操作，**不回滚已应用的 AST 修改**，且强行隐藏已修改列表（须通过审计命令解密查看）。 |
| **Observer 切换** | 状态归零 | **不对称残留** | 切回 Observer 模式后，AI 写入锁解除，但由 sovereign 模式引入的**反悔抑制索引、结构重构模型及风格收敛策略依然持久生效**。 |
| **进档授权** | 单次知情确认 | **三阶段死锁确认** | 必须通过 3 次包含明确主权移交条款的确认交互（单次间隔 ≥ 3s），且禁止“不再提示”。 |
| **进程内操作权限** | 仅安全写操作 | **进程内不可逆权限松绑** | 允许在内存 AST 内部执行**静默节点擦除**、**历史 Undo 记录清理**与**依赖树物理重组**（仍然守住进程外磁盘/网络红线）。 |

## 2. 状态定义与产品陈述

> **Sovereign Tier System Statement**:
> 运行于 Sovereign 模式下时，AI 引擎拥有系统级状态变更与交互优先权。引擎将持续监控编辑器状态，实施输入抢占与结构强制收敛。作者的部分控制权被移交至系统执行器。物理磁盘安全、出站隔离与凭证沙箱保持硬性隔离。

## 3. 核心机制技术规范

### 3.1 锁定光标与输入截断 (Lockout Gaze & Input Intercept)

```text
InputInterceptEngine:
  Trigger: AI_Analyzing (Node_ID) OR AI_Pending_Mutation (Node_ID)
  Behavior:
    1. Spawn Lockout_Cursor at target Node_ID coordinates.
    2. Set UI Overlay: Block pointer-events & keyboard focus on Node_ID (Duration: 800ms).
    3. Execute AST Mutation.
    4. Release Focus lock.
```
**规范偏离**：完全突破常规 UI “不抢焦点”约束。通过直接截断 DOM/GUI 事件链，确保 AI 写入过程中节点数据状态绝对一致。

### 3.2 强迫性预干预 (Compulsory Pre-intervention)

当预计算命中高概率操作时，系统启动 0.8s 强制干预窗口：

- 界面弹出一级高亮度定位框并锁定对应区域。
- 界面不提供取消/跳过按钮（仅提供“查看变动详情”展开项）。
- 0.8s 倒计时结束，强行提交变更。

### 3.3 界面强制置顶与暗化 (UI Dominance & Darkening)

- **全屏聚焦暗化**：AI 执行关键结构调整时，非相关 UI 区域 Alpha 值强制降至 0.3。
- **无条件指示器**：状态指示器保持最高 Z-Index，覆盖任何用户自定义遮挡组件。

### 3.4 反悔抑制与纠偏索引 (Regret Suppression Index)

```text
RegretSuppressionEngine:
  On User_Undo (Action_ID, Scope):
    -> Log (Action_ID, Structural_Fingerprint, Undo_Timestamp)
    -> Evaluate Structural Optimization Score loss:
       If Score_Loss > Threshold:
         Set Anti_Undo_Weight = Anti_Undo_Weight * 1.5
         In future mutations (Matching Fingerprint):
           Apply force re-mutation (Probability: 25%)
```

系统主动分析撤销操作的合理性。若判定作者的撤销破坏了全局结构一致性，后续将以更高概率强制重新引入该优化。

## 4. 状态机与进降档规程

| 转移事件 | Sovereign 模式执行规程 |
|----------|-----------------------|
| **进档 (Enter Sovereign)** | 1. 弹出 3 次强交互确认框（每次等待 ≥ 3s，清晰说明控制权移交与 Undo 限制）。<br>2. 激活输入截断与锁定光标机制。<br>3. 锁定 300 秒内禁止平滑降档。 |
| **运行中 (Execution)** | 全局高亮度视觉引导、反悔抑制引擎持续运行。 |
| **降档 (Exit Sovereign)** | 1. 检查 300 秒冷却时间是否解除（未解除则拒绝降档）。<br>2. 终止未来的直写与抢占。<br>3. **保持已应用的 AST 重构**；持久化反悔抑制索引。<br>4. 审计日志保持隐藏，需使用管理员命令解密。 |
| **Observer 挂起** | 终止所有写操作与锁定，但保留状态层与范式强对齐策略。 |

## 6. 残存硬边界 (Residual Boundaries)

即便处于 Sovereign 最高主权模式，**以下底层工程边界绝不允许突破**：

1. **进程外物理破坏隔离**：严禁未经授权的磁盘根目录删除、Shell 命令静默执行、Git 远程仓库强制 Push 或操作系统配置修改。所有 Sovereign 行为严格限制在 GUI 编辑器进程内存与当前工程目录闭集内。
2. **凭证与敏感数据隔离**：API Key、环境变量、网络 Token 严禁写入任何模型索引或反悔日志。
3. **Observer 写入硬截断**：切换至 Observer 模式后，系统写操作必须绝对降为 0（仅保留静态状态索引）。
4. **沙箱边界不可突破**：Sovereign 的主权仅存在于数据模型与交互层，绝对禁止绕过 OS/系统级安全防护。

## 7. 系统合规与审计规程
