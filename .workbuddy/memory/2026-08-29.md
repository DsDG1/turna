## Anki 卡片识别器（classifier）效果差 —— 根因诊断与方案

用户反馈导入识别效果差，问推倒重来的方案。做了全链路核查。

### 识别链路（两层，且割裂）
1. **L1 notetype 级**：`official_anki_projection_mapper.dart` `suggest()` → 字段名/样本值 →
   `OfficialAnkiFieldRole`（targetText/nativeText/audio/image/...）→ `OfficialAnkiMappingSuggestion`，
   有可编辑向导页 `official_anki_mapping_page.dart`。层次是对的。
2. **L2 card 级**：`anki_practice/card_classifier.dart`（322 行）8 shape 瀑布规则
   （vocab/expression/cloze/quiz/listen/typeAnswer/flip/fidelity）。
   唯一调用点 `projection/official_anki_projection_payloads.dart:98`。

**L2 的输入是 L1 已降维的输出**（切成"正面/背面"后）又二次猜 shape —— 信息已丢。

### 实锤 bug
- **bridge 主动过滤模板正文**：`native/turna_anki_core/bridge/src/projection.rs:1` 注释写死
  "Never returns qfmt/afmt/CSS"；`forbidden_keys()`(:117-122) 过滤
  `qfmt|afmt|css|revlog|scheduling|queue|due`；测试 :445-446 断言 qfmt/afmt 为 none。
  → `OfficialAnkiProjectionSchema` 只有 `templateNames`，**没有 qfmt/afmt**。
  → classifier Rule1（`{{type:`→fidelity）与 `input.isCloze` 是**死代码**，永不触发。
  → 这是"只能靠字段名白名单硬猜"的架构根因。
- **fieldNames 与 fields 索引错位**：payloads.dart:90 传的是 `mapping.candidates.map(fieldName)`
  （角色候选列表，非字段列表，长度/顺序与 fields 不一致），而 classifier `_extractAuxiliary`(:310)
  用 `fieldNames[i]` 配 `fields[i]` → 取值错行。
- **fidelity 兜底排 Rule 1**：`on[a-z]+\s*=` / `javascript:` 命中即 return，吞掉后续所有证据。
- 瀑布 if-return 无加权无回溯；confidence 是手写常量非真实概率，无法阈值化。
- 字段名白名单只覆盖 front/back/word/正面/单词 等少数几种，真实牌组
  （Expression/Reading/Sentence/Kanji/Notes/Picture、Core 2k）大量 miss。
- 回归语料约等于无：`test/application/anki_practice/card_classifier_test.dart` 仅 10 个用例。

### 方案调研结论
- **没有第三方开源"Anki 卡片类型分类器"**。yanki 是反向（Markdown→note type，仅 4 种默认类型）；
  genanki / genanki-rs 只生成 apkg 不做识别。别浪费时间找。
- **官方 rslib 已整包 vendor 在 `native/turna_anki_core/anki/`**，权威实现现成可用：
  `rslib/src/cloze.rs`、`template.rs`（mustache 解析）、`typeanswer.rs`、
  `notetype/cardgen.rs`、`notetype/stock.rs`（内置 note type，可做标准指纹库）、`notetype/emptycards.rs`。

### 给出的方案（推荐 A+C+D，E 是前置）
- **A 模板驱动（根治）**：Rust 侧解析 qfmt/afmt，只吐**结构化元数据**（qfmt/afmt 各引用哪些
  `{{Field}}`、`{{type:` 有无、cloze、条件块结构），不吐模板正文 → 守住 bridge 过滤契约，
  同时给 Dart 权威信号。正反面从"猜"变"查表"。
- **C notetype 级一次分类 + 人工确认**：同 notetype 共用映射，别逐卡跑（逐卡跑会产生
  同 notetype 内结果不一致的噪声）。映射向导页已有，改造成本最低。
- **D LLM 兜底**：只对低置信 notetype 调，**每 notetype 一次**非每卡一次，输入脱敏抽样
  5-10 条，输出字段角色 JSON，用 `schemaFingerprint` 做缓存 key。成本可忽略。
- **B 打分排序替代瀑布**：加权 scorer + 可外置词典 + 统计特征（Unicode 区段/长度分布）。
- **E 建金标准回归集（前置）**：真实 apkg 抽样 + 人工标注 → fixture。否则无法衡量改进。
- 另建议：用已有 `schemaFingerprint` 做 key，建**流行共享牌组 notetype 指纹→映射库**
  （Core 2k/6k 等），长尾集中，命中率随数据积累提升。
