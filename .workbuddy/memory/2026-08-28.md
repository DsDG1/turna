## 全项目架构分析（只读探查，未改动任何代码）

对 Turna（Flutter 土耳其语学习 App）做了一次完整架构审计。

**规模实测**：lib/ 手写 Dart 124,217 行（生成代码另 24,173 行），586 个 dart 文件，
157 个 view widget，70 个 injectable 类，59 条 AutoRoute 路由，263 个测试文件。
DB schemaVersion 21，约 32 张表（15 个 drift Table 类 + 约 17 张原生 SQL 管理）。

**分层代码量**：application 55.3k / views 46.8k / data 7.1k / domain 5.4k /
service 3.7k / core 2.0k / courses 1.0k / di 0.5k / routing 0.2k。
其中 `application/anki_official/` 独占 26,884 行（104 文件），是全项目最大子系统，占 21.6%。

**架构定性**：Clean Architecture 四层 + core/service/courses/routing/di 横向支撑。
Provider + ChangeNotifier 做状态，GetIt + Injectable 做 DI，AutoRoute 做路由，
drift + SQLite 本地持久化，Freezed 不可变模型。本地优先、无后端。

**发现的架构问题（重要，后续可复用）**：
1. views 层 10 个文件直接 import `data/`（home_page.dart 一处引 3 个）。
2. domain 层 3 个文件反向依赖 application/ 与 data/ —— 真正的依赖倒置：
   `domain/repositories/i_course_repository.dart` 接口引了 `data/course_database.dart` 实现。
3. core 层被污染：`core/text_styles.dart` → `views/theme.dart`；
   `core/fsrs_optimizer.dart` → `data/review_history_dao.dart`。
4. AI 层：`AiEngine` 是具体类无抽象接口，不可替换；API key 经 UI 层传递；
   无统一重试/退避；`AiErrorMapper` 靠字符串嗅探 HTTP 状态码。
5. 文档漂移：project-guide.md 仍写 schemaVersion 18（实际 21）、13 种 Interaction（实际 14）、
   ai/ 下有 hint/wish/course/tutor 目录（实际是 engine/companion/textbook）。

**已验证成立的优点**：AI 引擎确为全应用唯一 LLM 出口（全局仅 2 处 import http，
另一处是 WebDAV 备份）；渲染器插件化（Set<InteractionRenderer> via GetIt，
新增题型不改分发逻辑）；Anki 迁移用 write fence + owner authority 治理得克制。

**平台约束**：Android 仅提供 arm64-v8a 的 libturna_anki.so，iOS/Windows 硬编码不可用。

## 21:18 周边产品（spin-off）方向评估（只读，无改动）

用户问「这个项目的周边性产品可以是什么」。结论：**App 本体商业化天花板低
（§15 主动砍掉账号/内购/云同步/排行榜），真正值钱的是三块可剥离的能力资产。**

按「剥离成本 × 独立市场价值」排序：

1. **tool/gui 课程编辑器 → 独立产品（最佳）**。已是 PySide6 独立应用，自带
   pyproject + PyInstaller spec + 测试 + i18n；含 AI 课程工坊、教材导入
   （PyPDF2/python-docx）、教师视图。与 App 唯一耦合是「输出 Turkish 课程 JSON」，
   抽掉语种硬编码即可多语种。市场真空位：给语言教师做结构化课程的桌面工具几乎没有
   （Anki 编辑器是卡片维度无 CEFR 层级，其余靠 Excel）。
2. **lib/application/anki_official/ → flutter_anki_core package（技术壁垒最高，维护最重）**。
   26,884 行 / 104 文件，FFI 接 rslib（native/ 有 259 个 .rs）。pub.dev 上 Flutter+Anki
   基本都是自造轮子解析 apkg，能跑官方 scheduler 的极少。建议开源换影响力而非直接商业化。
   硬约束：Android 只提供 arm64-v8a 的 libturna_anki.so，iOS/Windows 硬编码不可用。
3. **lib/application/ai/engine/ → ai_engine package（剥离成本最低）**。约 2000 行纯 Dart，
   无平台代码、无 FFI。含 provider preset / 流式 / 缓存 / 取消令牌 / http client /
   配置持久化（API key 写入绕过日志）。

**低成本生态钩子**：课程包开放格式 + CLI 校验器（`lib/courses/course_validator.dart`
456 行已能校验结构，发布 JSON Schema 可让第三方替你产内容）；听力音频生成流水线
（tool/ 中已有 TTS 合成 + 混音脚本）；Turna 湿地鹤 IP 贴纸/主题。

**明确别碰**：FSRS 封装单独发（pub.dev 已有官方 `fsrs` 包，无差异）；
云同步/订阅版 App（推翻 ADR 本地优先全部决策 = 重做产品）；
多语种 App（编辑器支持 ≠ 内容能跟上，148 词的 Turkish 内容本身就是壁垒）。

**一个认知要点**：项目哲学约束的是**学习者端 App**，工具端/内容端不受此限——
所以课程编辑器做订阅收费不与「无内购」矛盾，边界要讲清楚。
