# Goal

在不改动任何安卓端逻辑的前提下：

1. **提醒事项**：让现有 Flutter `LocalReminderService`（每日复习提醒）在鸿蒙端**真正生效**——补齐鸿蒙通知所需权限、图标与初始化配置，安卓端逻辑保持原样。
2. **小艺直接解答题目**：在鸿蒙端新增"问小艺"入口，点击后**拉起系统小艺对话界面**并预填题目作为问题，用户在小艺里查看答案。无需输入任何 API Key，也不走现有 DeepSeek `/chat/completions` 流程。安卓端继续使用现有 DeepSeek AI hint 流程，不受影响。

# Scope / Non-goals

**In scope**
- 鸿蒙 `module.json5` 增加通知权限声明 `ohos.permission.PUBLISH_AGENT_REMINDER`。
- 鸿蒙端新增通知图标资源，使 `flutter_local_notifications` 的 `initialize(defaultIcon)` 能取到图标。
- 鸿蒙原生侧新增 `XiaoyiPlugin.ets`，通过 MethodChannel 提供一个 `askXiaoyi(prompt)` 方法，用 `startAbility` 拉起小艺。
- Flutter 侧新增平台门控（`Platform`/`kIsWeb`）的"问小艺"按钮逻辑，仅鸿蒙端显示；点击后通过 MethodChannel 调用原生拉起小艺。
- 现有 `_openAiHint` 在鸿蒙端改为：若用户开启"用小艺解答"，则走小艺通道（拉起），不要求 API Key；否则走原 DeepSeek 通道。安卓端行为不变。
- 设置页"学习"分类新增一个鸿蒙端可见的开关"用小艺解答题目（鸿蒙）"。

**Non-goals**
- 不在 app 内显示小艺返回的答案文本（拉起模式，答案在小艺界面内查看）。
- 不引入 HMS AI Kit / 端侧大模型推理。
- 不改安卓端 `local_reminder_service.dart` 的安卓分支逻辑。
- 不改现有 DeepSeek AI hint / wish / course 生成 / lesson helper 等流程。
- 不新增独立的"待办/自定义提醒列表"功能。

# Current State And Constraints

## 提醒
- Flutter 端 `lib/service/local_reminder_service.dart` 已用 `flutter_local_notifications` 实现 `periodicallyShow` 每日提醒，安卓/iOS 分支已配，**鸿蒙端无独立分支**。
- 鸿蒙版 `flutter_local_notifications`（pubspec 指向 `fluttertpc_flutter_local_notifications`）已在 `GeneratedPluginRegistrant` 注册。
- 该插件的 HAR `module.json5` 已声明 `ohos.permission.PUBLISH_AGENT_REMINDER`，但**当前项目 `ohos/entry/src/main/module.json5` 只声明了 `ohos.permission.INTERNET`**。鸿蒙端权限合并机制要求宿主 module 也声明同权限才会真正授予。
- 插件 `initialize` 需要从资源里按 `defaultIcon` 名取图标；当前代码传 `@mipmap/launcher_icon`，而鸿蒙端 `resources/base/media/` 只有 `icon.png`，无 `launcher_icon`。`initialize` 在取不到图标时仅打日志仍返回 success，但 `periodicallyShow`→`reminderAgentManager` 的提醒发布在无图标/无权限时可能静默失败。
- `init()` 中 `androidPlugin?.requestNotificationsPermission()` 仅对安卓生效；鸿蒙端的 `requestNotificationsPermission` 走插件 MethodChannel，但当前 Flutter 侧未对鸿蒙调用，导致通知可能未启用。

## 小艺
- 现有 AI hint 流程：`new_lesson_screen.dart` 的 `_openAiHint` → 读 `AiCourseProvider.config`，若 `!config.isComplete` 弹"去设置"对话框；否则 `AiHintProvider.explainQuestion` 走 `AiCourseService.requestChat`（DeepSeek `/chat/completions`，需 Bearer Key）。
- 鸿蒙端已有自定义插件模式（`RdbPlugin.ets`、`FilePickerPlugin.ets`），在 `EntryAbility.configureFlutterEngine` 注册。新增 `XiaoyiPlugin` 遵循同模式。
- 拉起小艺属于原生 `@kit.AbilityKit` 的 `UIAbilityContext.startAbility` 范畴，通过 `want` 指定小艺的 bundle/ability 或使用系统 AI 拉起 Action。本项目无现成小艺集成代码，需新增。

## ArkTS / 平台约束
- 鸿蒙原生插件用 ArkTS（`.ets`），需遵守 ArkTS strict 规则：无 `any`、无 `as` 断言、无对象字面量作类型。
- `XiaoyiPlugin` 的 MethodChannel 回调参数需显式类型，`call.argument<T>(key)`。
- Flutter 侧用 `Platform`（注意 `kIsWeb` 守卫）判断鸿蒙；鸿蒙端在 `dart:io` 的 `Platform` 上表现为 `Platform.isAndroid`? 实际 Flutter-OH 提供独立判断——需用 `defaultTargetPlatform` 或 `kIsWeb` + 自定义环境标识。**实现时用 MethodChannel 探测：在 `XiaoyiPlugin` 注册的 channel 调 `isSupported()` 返回 true 表示鸿蒙端可用，避免依赖 `Platform.is*`。**

# Design

## 1. 鸿蒙端提醒生效（仅改鸿蒙侧，安卓不变）

**`ohos/entry/src/main/module.json5`**：在 `requestPermissions` 增加：
```json5
{"name": "ohos.permission.PUBLISH_AGENT_REMINDER",
 "usedScene": {"abilities": ["EntryAbility"], "when": "always"}}
```

**鸿蒙通知图标**：在 `ohos/entry/src/main/resources/base/media/` 新增 `launcher_icon.png`（可复制现有 `icon.png`）。这样 `flutter_local_notifications` 的 `initialize(defaultIcon: '@mipmap/launcher_icon')` 在鸿蒙端能取到图标。

**Flutter 侧 `local_reminder_service.dart`**：在 `init()` 增加鸿蒙端通知启用与权限请求（不改安卓/iOS 分支）：
- 用 `defaultTargetPlatform` 判断非 web 后，对鸿蒙端调用 `_plugin.resolvePlatformSpecificImplementation`（无鸿蒙专用接口时，直接调用 `requestNotificationsPermission` 通用方法）。
- 实际做法：在 `init()` 中对所有非 web 平台统一调用 `_plugin.requestNotificationsPermissions()`（flutter_local_notifications 19.x 提供的跨平台权限请求 API；安卓端等价于现有 `androidPlugin?.requestNotificationsPermission()`，鸿蒙端走插件 MethodChannel 的 `requestNotificationsPermission`）。**保持安卓原有行为等价，不删安卓分支，仅补充通用调用作为鸿蒙端覆盖。**

**EntryAbility**：鸿蒙端 `EntryAbility.ets` 的 `onCreate`/`onWindowStageCreated` 需把 `globalThis.context` 设为 UIAbilityContext，因为通知插件的 `initialize` 用到 `globalThis.context`（见插件源码 `let uiAbility = globalThis.context`）。当前 `EntryAbility` 继承 `FlutterAbility`，需确认父类已设置；若未设置，在 `onCreate` 中补 `globalThis.context = this.context`。

> 备注：`periodicallyShow` 在鸿蒙端映射到 `reminderAgentManager` 发布定时提醒，需 `PUBLISH_AGENT_REMINDER` 权限——这是"真正生效"的关键。

## 2. 新增小艺拉起插件（鸿蒙原生侧）

**新文件 `ohos/entry/src/main/ets/plugins/XiaoyiPlugin.ets`**：参照 `FilePickerPlugin.ets` 结构。
- Channel: `com.varnamala/xiaoyi`
- 方法 `askXiaoyi`：接收 `{prompt: string}`，构造 `want`，用 `this.ctx.startAbility(want)` 拉起小艺。
- 拉起小艺的 want 方案（按鸿蒙公开实践）：优先用系统 AI 助手拉起 Action `ohos.want.action.voiceAssistant` 或小艺的 bundleName/abilityName。实现时在插件内用 try/catch 包裹 `startAbility`，失败时通过 `result.error` 回传错误信息给 Flutter，由 Flutter 侧给用户提示。
- 方法 `isSupported`：返回 `true`（仅鸿蒙端注册，存在即代表支持），用于 Flutter 侧平台门控。
- ArkTS 注意：`want` 用对象字面量赋值给显式 `Want` 类型变量；`call.argument<string>('prompt')` 显式泛型。

**`EntryAbility.ets`**：在 `configureFlutterEngine` 增加 `flutterEngine.getPlugins()?.add(new XiaoyiPlugin())`。

## 3. Flutter 侧"问小艺"入口与门控

**新文件 `lib/service/xiaoyi_service.dart`**：
- `class XiaoyiService`（`@lazySingleton`，注入 DI）。
- 单例 `MethodChannel('com.varnamala/xiaoyi')`。
- `Future<bool> get isSupported async`：try `invokeMethod('isSupported')`，成功且 true 则支持；失败/非鸿蒙则 false。缓存结果。
- `Future<void> ask(String prompt)`：`invokeMethod('askXiaoyi', {'prompt': prompt})`；抛异常时由调用方 catch 显示 SnackBar。
- 无 `apiKey`、无网络——纯原生拉起。

**`lib/application/ai/ai_hint_provider.dart` 或新 `xiaoyi_hint_provider.dart`**：为最小侵入，**不改 `AiHintProvider`**，而是在 `new_lesson_screen.dart` 的 `_openAiHint` 中增加鸿蒙小艺分支。

**`lib/views/lesson/new_lesson_screen.dart` 的 `_openAiHint` 改造**（安卓行为不变）：
```
1. final xiaoyi = getIt<XiaoyiService>();
2. final useXiaoyi = settings.useXiaoyiHint && await xiaoyi.isSupported;
3. if (useXiaoyi) {
     // 构造与 AiQuestionContext 同样的 prompt 文本（复用 _buildExplainPrompt 逻辑或直接拼 promptLabel+options）
     await xiaoyi.ask(promptText);
     return; // 不弹 sheet、不调 DeepSeek
   }
4. // 原有逻辑：config.isComplete 检查 → explainQuestion → sheet
```
- 安卓端 `xiaoyi.isSupported` 永远 false（channel 不存在/无插件），自动落入原 DeepSeek 流程，行为完全不变。
- prompt 文本：复用 `AiHintProvider._buildExplainPrompt` 的拼装逻辑——为复用，将该方法/逻辑提取为顶层函数 `String buildXiaoyiPrompt(AiQuestionContext ctx)` 放到 `ai_hint_provider.dart` 同文件或 `ai_prompt_builder.dart`，鸿蒙分支调用它生成纯文本发给小艺。

## 4. 设置页开关

**`lib/application/settings_provider.dart`**：新增持久化字段 `useXiaoyiHint`（bool，默认 false），存 `settings.useXiaoyiHint`。仿照 `dailyReminderEnabled` 的 get/set 模式。

**`lib/views/settings/widgets/settings_reminder_section.dart` 同目录新增 `settings_xiaoyi_tile.dart`**：一个 `SettingsToggleTile`，标题"用小艺解答题目"，副标题"鸿蒙端：点击题目 AI 按钮拉起小艺，无需 API Key"。**可见性**：在 tile 内 `FutureBuilder` 包 `XiaoyiService.isSupported`，仅鸿蒙端返回 true 时显示该 tile；安卓端不渲染，完全无影响。

**`settings_page.dart`**：在"学习"分类（case 1，提醒 tile 附近）按 `SettingsXiaoyiTile()` 插入（其内部自管可见性）。

## 5. DI 与生成代码

- `XiaoyiService` 用 `@lazySingleton` 注解 → 需运行 `flutter pub run build_runner build --delete-conflicting-outputs` 重新生成 `injection.config.dart`。
- `SettingsProvider` 新字段无需生成代码（手写 get/set）。

# Risks And Compatibility

- **小艺拉起 want 方案不确定**：鸿蒙小艺的精确 bundleName/abilityName 或拉起 Action 可能随系统版本变化。实现时优先用系统级 AI 助手拉起 Action；若拉起失败，`startAbility` 抛错经 MethodChannel 回传，Flutter 侧 SnackBar 提示"无法拉起小艺"。不影响 app 其他功能。
- **`PUBLISH_AGENT_REMINDER` 为 system_grant 权限**：声明即授予，无需运行时弹窗；但部分设备需用户在系统设置开启"允许通知"。文档应在开关副标题提示用户。
- **`globalThis.context` 依赖**：若 `FlutterAbility` 父类已设置则重复赋值无害；若未设置则补上是必需的。实现时先读父类源码确认，避免重复。
- **`Platform.is*` 在 Flutter-OH 的行为**：不依赖 `Platform`，改用 `XiaoyiService.isSupported` MethodChannel 探测，规避平台判断歧义。
- **build_runner 重新生成**：`injection.config.dart` 会变动，需确认无其他注入项被覆盖。
- **`flutter_local_notifications` 19.x `requestNotificationsPermissions()`**：需确认该版本提供跨平台通用方法；若仅有 `Android*`/`Darwin*` 专用接口，鸿蒙端则直接 `invokeMethod('requestNotificationsPermission')` 通用调用。
