# HarmonyOS RDB Bridge - Full Functionality Plan

## Goal

Enable complete Varnamala functionality on HarmonyOS (OHos) by bridging the native `@kit.ArkData relationalStore` to Flutter's `drift` ORM via MethodChannel. This restores:
- Course database loading (sections/units/lessons/vocabulary/grammar/expressions)
- AI course generation and save (`AiCourseProvider.save()`)
- Textbook import (`TextbookImportProvider`)
- Anki deck import (`AnkiImporter` → `CourseDatabase`)
- SRS review (already uses SharedPreferences, verified working)

## Scope / Non-goals

**Included:**
- CourseDatabase RDB bridge (9 tables + migrations)
- AI course save flow
- Textbook import save flow
- Anki import metadata storage
- SRS review (already functional via SharedPreferences)
- Android/iOS unchanged

**Not included:**
- Anki `.apkg` file parsing on OHos (requires separate approach — see Risks)
- Cloud sync / cross-device data migration
- HarmonyOS-specific UI changes

## Current State And Constraints

| Settings / theme / locale | SharedPreferences | ✅ Working |

### Key Constraints

1. **`sqlite3_flutter_libs` has no OHos build** — `NativeDatabase(file)` fails at compile time
2. **`drift` is pure Dart** — confirmed working on OHos with Dart 3.6.2 (needs `^2.22.1`)
3. **Anki importer uses `sqlite3` FFI directly** — `lib/application/anki/anki_importer.dart:74` calls `sql.sqlite3.open()` to read `.apkg` files. This is a SEPARATE sqlite3 usage from CourseDatabase and will ALSO fail on OHos.
4. **Project already uses `dependency_overrides`** for OHos-adapted plugins (shared_preferences, path_provider, url_launcher, etc.) from `openharmony-tpc` / `openharmony-sig` git repos

### Existing OHos Guards (to be removed)

## Design

### Architecture

```
┌─────────────────────────────────────────────────────────────────────┐
│                        Flutter (Dart)                               │
│                                                                     │
│  drift CourseDatabase                                               │
│       │                                                             │
│  HarmonyOsRdbExecutor (QueryExecutor)                               │
│       │                                                             │

└───────────────────────┬─────────────────────────────────────────────┘
                        │ MethodChannel (JSON RPC)

```

### RDB Plugin API

| Method | Direction | Purpose |
|--------|-----------|---------|
| `openDb(name: string)` | Flutter → ArkTS | Open/create RDB store |
| `executeSql(sql: string, params: Array)` | Flutter → ArkTS | INSERT/UPDATE/DELETE/DDL |
| `query(sql: string, params: Array)` | Flutter → ArkTS | SELECT → `List<Map<String, Object?>>` |
| `close()` | Flutter → ArkTS | Close store |

### drift QueryExecutor Mapping

| drift Method | RDB Call | Notes |
|--------------|----------|-------|
| `runInsert()` | `executeSql()` | Returns 0 (no lastInsertRowId; project uses TEXT PKs) |
| `runUpdate()` | `executeSql()` | Returns 0 (affected rows not exposed) |
| `runDelete()` | `executeSql()` | — |
| `runSelect()` | `query()` | ResultSet → `List<Map<String, Object?>>` |
| `runCustom()` | `executeSql()` | DDL (CREATE TABLE, etc.) |
| `runBatched()` | Multiple `executeSql()` | Sequential execution |
| `beginTransaction()` | `Transaction()` | RDB auto-commits each statement |

### Anki Import Handling

The `AnkiImporter` class uses `sqlite3` FFI to read `.apkg` files (which are ZIP archives containing a SQLite database `collection.anki2`). This is independent of CourseDatabase.

**Options for OHos:**

1. **Extend RDB bridge** — Copy `collection.anki2` to app sandbox, open via `relationalStore.getRdbStore()`, query via MethodChannel. Requires plugin extension to support arbitrary DB file paths.
2. **Graceful fallback** — Show "Anki import not available on HarmonyOS" message, same as current course DB behavior.
3. **Pure Dart parser** — Use a pure Dart SQLite reader (slow, limited SQL support).

**Recommended:** Option 2 (graceful fallback) for initial release. The `file_picker` plugin is already adapted for OHos, so users can still pick `.apkg` files — the importer will show a platform-unsupported message instead of crashing.

## Risks And Compatibility

| Risk | Impact | Mitigation |
|------|--------|------------|
| **RDB `executeSql` doesn't return lastInsertRowId** | drift autoincrement PKs would break | Project uses TEXT PKs exclusively — no impact |
| **RDB transaction semantics differ** | Batched operations may not be atomic | Each `executeSql` is atomic; drift's `transaction()` wraps with BEGIN/COMMIT |
| **MethodChannel serialization overhead** | Cold start slower than FFI | Acceptable — course data loads once per session |
| **`ResultSet` not closed** | Connection leak, eventual failure | Ensure `rs.close()` in ArkTS after each query |
| **Anki `.apkg` parsing unavailable** | Anki import feature missing on OHos | Graceful fallback message; feature not critical |
| **drift version compatibility** | `^2.16.0` may not work with OHos Dart 3.6.2 | Upgrade to `^2.22.1` (confirmed working) |
| **BLOB column type** | RDB bridge returns null for BLOBs | Project has no BLOB columns |
| **`sqflite` not used** | No sqflite dependency needed | Using direct RDB bridge instead |

## Rollback

If the RDB bridge fails:

1. **Revert `lib/service/locator.dart`** — restore the OHos skip guard
2. **Revert `lib/main.dart`** — restore the OHos return guard
3. **Revert UI files** — restore OHos error messages
4. **Delete `lib/data/rdb_query_executor.dart`**
5. **Delete `ohos/entry/src/main/ets/plugins/RdbPlugin.ets`**
6. **Revert `GeneratedPluginRegistrant.ets`**
7. **Revert `pubspec.yaml`** drift version

The project returns to its current state: OHos shows "Course database not available" but Android/iOS remain fully functional.
