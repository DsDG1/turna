# 修复 Anki 大牌组导入卡住/闪退

## 根因（已确认）
1. **卡住/ANR**：解析、媒体复制、全部 SQL 都同步跑在 UI 主 isolate，无让出点，第四阶段的加载动画排了帧也渲染不出来。
2. **闪退/OOM**：解压时整包 `readAsBytesSync` + `decodeBytes` + 每条目 `List<int>.from` 多份拷贝同时驻留内存（上限 512MB/2GB），大牌组直接打爆堆。

已验证：parse 平台层纯 `dart:io`/`archive`/`sqlite3`（无 method channel，isolate 安全）；`AnkiCollection` 等 freezed 数据类可跨端口传递；全仓库 drift 调用均异步，无同线程假设。

## 改动清单（按实施顺序）

### 1. 数据库移入后台 isolate（修事务阶段冻结）
`lib/service/locator.dart:320`：`CourseDatabase(NativeDatabase(file))` → `CourseDatabase(NativeDatabase.createInBackground(file, isolateSetup: ...))`。
- `isolateSetup` 内复用 `lib/application/anki_official/storage/official_anki_sqlite.dart` 的 sqlite3 loader override（`open.overrideFor`，Linux/Android `libsqlite3.so`）。
- OHOS 分支（MethodChannel executor）不动；测试均自建 executor，不受影响。

### 2. copyMedia 移入 Isolate.run（修媒体复制冻结）
`lib/domain/audio/anki_audio_resolver.dart:29-78`：
- 先在主 isolate 用 `getImportMediaPath` 解析 `targetDir`（path_provider 仅主 isolate 可用），再把循环体挪进 `Isolate.run`（纯 dart:io 复制，返回 report）。签名不变（避免影响测试 fake 子类）。实现时确认 `ankiCopyFile` 等为纯 dart:io。

### 3. assembler 让出改为时间片
`lib/application/anki/anki_deck_assembler.dart:258-259, 358-366`：固定"每 40 张卡片让一次"改为 Stopwatch 判定（距上次让出 ≥16ms 才 `Future.delayed(Duration.zero)`），单卡耗时大时不再冻结。onProgress/取消语义不变。

### 4. 解压改流式（修 OOM 闪退）
`lib/application/anki/anki_import_platform_io.dart`：
- 新增 `ankiExtractArchiveToDisk(apkgPath, destDir, ...)`：`ZipDecoder().decodeStream(InputFileStream(path))` + 逐条目 `entry.writeContent(OutputFileStream)`（archive 4.0.9 已确认支持），不再整包进内存、无二次拷贝；通过回调上报每条目名/字节数，供 importer 做 `maxEntryBytes`/`maxUncompressedBytes` 上限检查（按实际写入量累计）与进度。
- 新增 `ankiHashFileSha256(path)`：RandomAccessFile 1MB 分块 + `sha256.startChunkedConversion`。
- `anki_importer.dart` 内 `_safeArchiveEntryName` 过滤逻辑保留，接到新平台函数上。

### 5. parse 移入 spawn 的 worker isolate（修解析阶段冻结，保进度+可取消）
`lib/application/anki/anki_importer.dart`：
- **公开 `parse()` 签名不变**，调用方（导入屏、cutover、internal page）零改动。
- 内部改为 `Isolate.spawn`（`debugName: 'anki-import-parser'`）+ 双端口协议，参考 `official_anki_session.dart` 现有模式：
  - worker→主：进度 `(p, msg)`（原 onProgress 触发点逐页发送）、完成（`AnkiCollection`）、错误（序列化 message+code，主侧重建 `AnkiImportException`/`AnkiImportCancelled`）。
  - 主→worker：cancel 命令；主 isolate 用 100ms `Timer.periodic` 轮询调用方 `isCancelled()`，置位后发一次。
  - worker 在现有分页边界检测取消 → 抛 `AnkiImportCancelled` → 走原有 `finally` 清理临时目录；成功时保留解压目录（媒体复制后续要用）。
  - worker 体内使用改动 4 的流式解压；sqlite 句柄只留在 worker 内；OHOS 守卫保留在主侧 spawn 之前。

### 6. cutover 批量化（小、低优先）
`lib/application/anki_official/migration/official_anki_new_import_cutover.dart:84-109`：逐行 `await upsertNote/upsertCardMeta` → 分批（500/批）调用已有的 `upsertNoteBatch`/`upsertCardMetaBatch`（`lib/data/anki_note_dao.dart:579/601`）。

## 测试
- 新增 `test/anki/anki_importer_isolate_test.dart`：程序化构建最小 .apkg（sqlite3 建表 + ZipEncoder 打包），断言：解析结果正确、onProgress 收到递增进度、取消 → 抛 `AnkiImportCancelled` 且临时目录被清理、超限条目 → `AnkiImportException`。
- 新增 copyMedia 隔离测试：临时目录 + 假媒体文件 + 路径穿越用例（`../evil` 记 failed）。
- 不重命名屏内 `AnkiImporter` / `AnkiImportFacade.resolve`（`official_anki_license_hook_test.dart:36-38` 有源码字符串断言）。
- `flutter analyze` + 全量 `flutter test`。

## 验证标准
- 导入大牌组时第二/第四阶段动画持续转动、进度条推进、取消按钮即时生效、无 ANR。
- 解压期间内存占用平稳（O(单条目) 而非 O(整包)）。

## 风险与备注
- `createInBackground` 为仓库首次使用；已核查无 `.executor` 访问、无同步 drift API、OHOS 走独立分支。
- 官方 Rust 引擎路径已隔离在 worker（无需改动）；官方导入期间主 isolate 本就空闲，进度轮询属锦上添花，本次不做。
