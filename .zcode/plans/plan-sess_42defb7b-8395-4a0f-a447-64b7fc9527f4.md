# 性能优化 #3/#4/#5/#6 实施方案

## #3 AI 流式渲染：消除 O(n²) 全文档重排

**1. `src/dialogs/ai/chat_view.py` — ChatView 追加式流式渲染**
- 现状：`render_streaming` 每次 flush（120ms）重建全部历史消息 HTML 并 `setHtml()`，QTextDocument 全文重解析，对话越长越卡。
- 改法：新增流式快速路径状态 `_stream_msg_count` / `_stream_anchor`：
  - `render()` 后使状态失效；
  - `render_streaming()`：若消息数变化（新回合首次 flush）→ `setHtml(render_chat_html(...))` 一次 + `QTextCursor` 移到文末记录 anchor + `insertHtml(ai_bubble_html(partial))`；
  - 消息数不变（后续 flush）→ 从 anchor 选到文末、`removeSelectedText()`、`insertHtml(新 partial)`——只重排末条气泡，历史不动。
  - anchor 之后的内容每轮全量重建，无空块累积；`render_streaming_html` 纯函数保留导出（既有单测依赖）。
- 扩展窗（`chat_expand_window.py:125`）内部就是 ChatView，自动受益，无需改动。

**2. `src/dialogs/ai_generator_dialog.py` — 流式护栏 + 最终全文**
- 新增 `_STREAM_TEXT_LIVE_LIMIT = 8192`（对齐 design_panel 的 `_STREAM_JSON_LIVE_LIMIT`）。
- `_flush_stream_view(self, final: bool = False)`：
  - wish/explain 流：非 final 且超限 → `explain_label.setPlainText("解释生成中… 已接收约 N 字符")`；否则/或 final → 现行 `_escape_html` 全量 setHtml；
  - normal JSON 流：非 final 且超限 → 只更新 `stage_label` 计数（编辑器冻结在最后未超限内容）；final → 全量 `setPlainText`（完整 JSON 预览）。
- `_finish_stream()`（:1318）改传 `final=True`——**关键**：此对话框的最终全文就是靠收尾 flush 渲染的，护栏不能吞掉最终内容。`_begin_stream` 重置逻辑不变。

**3. `src/dialogs/ai/design_panel.py` — explain 流补护栏**
- `_flush_stream_views` 的 "explain" 分支（:523-524）：`_explain_stream_buffer` 超过 8192 字符时改渲染计数提示（复用 `_render_explanation(f"（解释生成中… 已接收约 N 字符）")`），最终全文由 `_on_explanation`（:617，独立入口）渲染，不受影响。

## #4 课程总览：搜索防抖 + 去嵌套重复过滤

`src/widgets/course_overview.py`：
- `__init__` 增加 250ms 单发 `_filter_timer`（对齐 app.py 树刷新防抖惯例）；`_on_filter_changed` 只 `start()` 定时器，`timeout → _render`。课型按钮/清除过滤仍即时 `_render`（单击事件无连击问题）。
- `_render`（:243-247）消除嵌套过滤：用已算好的 `visible` 集合派生 `visible_sids = {sid for sid, _lid in visible}`，`for section in sections: if sid not in visible_sids: continue`——去掉每个 section 重复跑 `filter_lessons([section],…)` 的 O(sections×lessons)。
- `_clear_chip_style_cache()`（:222）改为只在主题变化时清：缓存键/哨兵记录当前 palette 标识（`theme_tokens.current_palette()` 的标识），主题没变就跨 render 复用 chip 样式缓存。（实现时先读文件头部 `_chip_style` 实现再落定具体哨兵。）
- `tests/test_course_overview.py`：`test_search_filters_chips`（:96）在 `setText` 后补显式 `_render()`（:108 的既有模式）；新增防抖行为测试（`textChanged` 后 `_filter_timer.isActive()` 为真且未立即渲染）。

## #5 保存线程化（交互保存走 AiRequestWorker）

`src/app.py`：
- `_on_save`（:1403，菜单/Ctrl+S/palette 三入口共用）改为异步：
  - 忙判定：`self._save_worker` 运行中 → 状态栏提示并返回；
  - 冻结编辑：`save_action.setEnabled(False)` + `centralWidget().setEnabled(False)` + 状态栏"保存中…"——复刻原同步冻结的数据安全语义（保存线程遍历课程 dict 期间 UI 无法再改模型），但 UI 线程保持响应；
  - `AiRequestWorker(self.adapter.save)` 跑重活（临时目录写盘 + validate + 备份 + 替换 + deepcopy + lint 全在后台）；
  - `result_ready` → 主线程执行与今天完全相同的收尾（`tree.refresh()`、`setClean`、状态栏、失败时校验报告）并解冻；`error_occurred` → 状态栏报错并解冻；`completed` → 清引用。
- `closeEvent`：若保存 worker 在跑，先 `wait()` 再走关闭流程（写盘竞态防护；关闭时等待与今天同步保存等价）。
- `app.py:1305`（TTS 前置保存）、closeEvent 自动保存、git push 前保存**保持同步**（模态流程/终端路径，冻结无感知）。
- 测试（test_app.py）：stub `adapter.save` 返回 ok/失败两种，`processEvents` 自旋等 worker 完成，断言状态栏/解冻/`setClean`；忙态重入测试。

## #6 教材库 Git 操作与 Goal LLM 线程化

**1. `src/dialogs/textbook_library_dialog.py`**（仿 `git_library_dialog._run_git_async:1347` 模式）：
- 新增 `_run_git_async(label, fn, *args, on_ok, error_title)` 私有 helper：AiRequestWorker + 上一 worker 取消/断连 + `_git_busy` 状态（禁用相关按钮 + 等待光标 + 状态文案）。
- `_on_import_from_git`（:342）：选远程后 → 异步 `git.clone`；成功回调里继续文件选择/语言选择/建项目（UI 模态步骤仍在主线程）；失败 → critical 弹窗 + 解忙。
- `_on_publish_to_git`（:396-432）：选远程后 → 一个 worker target 串起 `load_project + clone + 写 sections/index JSON + commit_and_push`（纯后端链）；成功 → 成功弹窗 + `mark_synced`；任步失败 → 对应错误弹窗。`load_project` 的大 JSON 读取顺带移出主线程。
- `tests/test_textbook_library_dialog.py`：既有 git 用例改为等 worker 完成的自旋 helper（`processEvents` 直到 `_git_worker` 清空，带超时）。

**2. `src/application/goal_controller.py`**：
- `experience_goal_plan`（:653）与 `experience_goal_run`（:775）：当 `expand=True` 且 `is_goal_llm_enabled(settings)` 且**非 headless**（`_is_headless_ui()` 守卫，保证无 Qt 环境的测试/CLI 走同步）时，把 `build_plan_for_host(host, goal_text, expand=True)` 放进 AiRequestWorker，先 `_status(host, "Goal 规划中（AI 扩展）…")`；`result_ready` 后执行抽取出的续体函数（记录事件 + `show_plan_dialog` + 状态；run 路径续接沙箱流程）。本地/未启用路径完全不变（同步）。
