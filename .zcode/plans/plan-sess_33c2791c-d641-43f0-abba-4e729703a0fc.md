# 远程备份与手动同步 — P1 实施计划

## 目标 / 非目标

**目标**：设置页新增「远程备份」子页面，支持配置自建 WebDAV 服务器（后续坚果云同协议直接兼容），手动「立即备份」与「从远程恢复」。备份覆盖**全部用户数据**：prefs 进度/设置超集、course.db、官方 Anki collection（collection.anki2 / collection.media / collection.media.db2 / official_catalog.sqlite）、legacy anki_media/。媒体按内容哈希增量上传。

**非目标（明确不做）**：记录级双向同步（多设备 merge）、自动定时备份、备份包加密（P2）、坚果云实测适配（P2）、OHOS 支持（入口隐藏，提示"暂不支持"）、WebDAV 凭据/AI API key 明文入备份包。

**决策记录**：媒体包含（内容寻址增量）；`ai.engineConfig` 备份时剥离 `apiKey` 字段；平台 = Android/iOS/桌面完整，OHOS 隐藏入口。**零新增 pubspec 依赖**（复用 http / archive / crypto / sqlite3）。

## 二、备份包与远端布局规范

**core.zip 内部结构**（archive 打包，均带 SHA256SUMS 清单）：
```
meta.json            # appVersion/buildNumber、driftSchema(18)、catalogSchema(8)、createdAtUtc、deviceLabel、平台
prefs.json           # 进度/设置超集快照（见下）
course.db            # VACUUM INTO 一致性快照
collection.anki2     # VACUUM INTO（引擎未建 collection 时记 absent 标记）
official_catalog.sqlite / collection.media.db2   # 同上
media_manifest.json  # { "<logicalPath>": {sha256, bytes} }（anki_media/<importId>/… 与 official/collection.media/…）
```

**prefs 超集清单**：现有 `_progressManifest`（export_service.dart:30-77）全部 + `srs.desiredRetention/fsrsParameters/fsrsOptimizedAt/fsrsOptimizedReviews` + 无障碍 6 项 + `settings.autoRotate/uiLocale` + 前缀 `settings.autoReadOnTap.` / `settings.nativeLang.` + `anki.preRenderEnabled/captureDelaySec/liteThreshold/forceDisableJs/dailyNewLimit/dailyReviewLimit/dailyChallengeIncludesAnki` + `courseScope/courseOrder` + `ai.savedExplanations/replyLanguage/depth/allowRevealAnswer/injectLearnerContext/recentCompanionTasks` + `fun.autoAnswer/allAchievementsUnlocked` + `ai.engineConfig`（**剥离 apiKey 后写入**）。排除：每日计数类（`anki.newDoneToday/reviewDoneToday/limitsDate`、`anki.deck.` 前缀）、`system.healthEvent`、WebDAV 自身配置 key。实现为 exact keys + include/exclude 前缀三段式，按 live key set 过滤（沿用 ExportService 做法）。

**远端布局**：
```
/TurnaBackup/
  manifest.json                       # 原子写：PUT manifest.json.tmp → MOVE 覆盖（最后写）
  backups/bk-<millis>-<rand4>/core.zip
  media/<sha256>                      # 内容寻址媒体对象，只增不删（GC 留 P2）
```
manifest.json 含 schema、backupId、createdAtUtc、deviceLabel、appVersion、drift/catalog schema、coreZip 的 sha256+字节数+对象路径、媒体统计、history（最近 5 份）。上传成功后删除超出保留数（5）的旧 backups/ 目录。

## 三、关键技术方案

**一致性快照（BackupSnapshotService）**：
1. 守卫：Anki 复习会话/导入 saga 进行中则拒绝（提示稍后再试）。
2. course.db：drift `customStatement("VACUUM INTO '<staging>/course.db'")`（路径单引号转义；项目 customStatement 有大量先例，如 anki_note_dao.dart:44-100）。
3. collection.anki2 / official_catalog.sqlite / collection.media.db2：裸 `sqlite3` 包只读连接 + `VACUUM INTO`（官方 create_backup 原生桥在 worker 模式下 UI 不可达，且 VACUUM INTO 对在线库产出单库一致快照，无需关引擎；跨库微小漂移可接受——ADR 0036 已定 Turna Drift 只存可重建投影）。
4. 媒体：遍历 `anki_media/*/` 与 `collection.media/`，复用分块哈希 `ankiHashFileSha256`（anki_import_platform_io.dart:54）；跳过 `backups/`、`engine.json`。
5. 产出 staging 目录 + core.zip + 待上传媒体去重表（sha → 本地路径）。

**WebdavClient**（package:http，`BaseRequest` 自定义 method）：`testConnection`(OPTIONS)、`exists`(HEAD)、`mkcolRecursive`(容忍 405)、`put`(StreamedRequest + `openRead` 流式上传大媒体)、`get`(流式落盘 + 边下边算 sha256)、`delete`、`move`(Overwrite:F)。Basic Auth；401 映射为专门异常（凭据错误文案）；超时与网络异常映射。自签证书选项留 P2（先用正规证书或局域网 http）。

**配置持久化**：单 key `remoteBackup.config` JSON（含密码），经裸 `StreamingSharedPreferences` 写入绕过日志——完全照抄 `ai_engine_config_holder.dart:82-89` 模式。备份包永不包含该 key。

**恢复流程（RemoteBackupService.restoreToStaging）**：GET manifest → 下载 core.zip → 校验 sha256 → 解包到 `<appSupport>/restore_staging/`（先清空）→ 校验 SHA256SUMS → 按 media_manifest 逐对象下载（校验哈希，已存在同哈希跳过）→ **最后**写 `restore_pending.json` 标记 → 提示用户重启应用。

**启动应用（RestoreApplier）**：挂载在 `setupLocator()` 内 locator.dart:262（prefs 就绪）之后、:299（course.db 打开）之前——此点官方 profile 也尚未被打开（catalog 首开在 main.dart:112）。流程：无标记则跳过 → 复核 staging 完整性 → **版本守卫**：staged course.db 的 `PRAGMA user_version` 与 catalog schema 超过当前版本（18/8）或备份 appVersion 更新时拒绝应用，写提示 key 待 UI 弹"请先升级应用" → prefs 逐 key 写回（runApp 前无读者）→ course.db 等库文件用 `.restore-partial` + rename 原子替换（照抄原生 restore_backup 模式）→ 媒体对象按 logicalPath 落盘（同哈希已存在则跳过）→ 清 staging 与标记 → 记 `remoteBackup.lastRestoredAt` 供启动后 SnackBar 提示。崩溃安全：标记最后写、rename 原子；任何一步失败保持原状。

## 五、实施步骤（每步含测试，逐步可提交）

## 六、风险与对策

- **大文件上传中断**：WebDAV 无断点续传，媒体按对象分文件（单文件通常 < 数 MB）+ 整体重试；core.zip 几~几十 MB 可接受整传。
- **快照期间写入**：复习守卫 + VACUUM INTO 单库一致 + 投影可重建（ADR 0036）+ 恢复后既有 seed/OfficialFirstReanchor 自愈内容表。
- **凭据明文**：与 AI key 同级风险，绕日志存储 + 隐私文案更新 + 备份包不含凭据。
- **恢复中断/断电**：staging + 标记最后写 + 原子 rename；未完成标记则启动不应用任何变更。
- **跨版本**：manifest 记 appVersion/schema，恢复侧守卫拒配"来自更新版本的备份"。

预计新增约 2000 行（含测试），不动现有业务逻辑；ExportService 与旧导出入口保持原样。
