> 上游文档：[README.md](./README.md)（总目标与六步计划）；前置：[step1.md](./step1.md)（已完成，收据已回填）。
> Step 2 只做一件事：**产出并通过 ADR 0043 的评审**——新架构长什么样、doc 41/42 每一个「中途杀进程」的场景在新架构里怎么办。

## 任务 A：设计输入研究

回答「设计的事实基础是什么」。以下输入已按 2026-08-31 工作树核实完毕：

1. **中断场景全集归并**（→ ADR §K1–K14）：
   - doc 41 §7.2 Recovery matrix（13 行）、§7.4 存量无主数据、§16.6 Android 强杀矩阵（11 场景，含 debug/release 双跑纪律）；
   - doc 42 §5.5 强杀恢复矩阵（5 行）、§10.2 强杀矩阵（4 行）；
   - step1.md「真机新发现清单」6 条（ANR、切换异常、pending_cleanup、日志静默、prefs 丢失、测试缝隙）。
   - 归并原则：同一物理场景只留一行，出处并列；v2 新增场景（配置区写、视图重建、迁移事务）显式标出。
2. **存储现状盘点**：四个 SQLite 库（`collection.anki2`、`collection.media.db2`、`official_catalog.sqlite` 18 张表、`course.db` 约 20 张 anki 表，`kSchemaVersion = 22`）；contract 1.11、ops 1–40（38 个在用，下一个可用编号 41）。
3. **必须继承的约束**：ADR 0036（rslib 唯一核心、钉 commit）、ADR 0037（统一复习愿景——砍投影只留复习器已被 doc 42 否决）、ADR 0042（staging-first 六条决策，v2 原样继承）、doc 41 §3 不变量与 §16.7 NO-GO 条件。
4. **Step 1 教训**（设计级，不是 bug 级）：测试缝隙会撒谎 → 入口测试必须贴真实挂载点；「谁负责打开引擎」必须有唯一答案；厂商 logcat 不可作为唯一观测通道。

## 任务 C：评审与定稿（Step 2 的唯一剩余门槛）

评审人逐条过以下检查表，全部 ☑ 才能把 ADR 状态改为「已接受」；任何一条 ✗ 则回任务 B 迭代：

- [ ] **场景完整**：doc 41 §7.2/§7.4/§16.6 + doc 42 §5.5/§10.2 的每一个场景，在 K1–K14 中能找到对应行（无遗漏、无合并丢语义）；
- [ ] **逐条有答案**：K1–K14 每行的答案具体到机制（staging 删除 / usn diff / 幂等重放 / 单事务回滚 / quarantine），没有「待定」「尽量」「应该」；
- [ ] **无猜测原则**：任何一行不依赖「猜测已提交/未提交」（doc 41 §3.4 铁律）；
- [ ] **决策自洽**：D1–D9 之间无矛盾（尤其 D2 配置区 ↔ D4 账本边界、D3 视图 ↔ D5 表收敛）；
- [ ] **表收敛无悬空**：附录 A 每格有去处；Q2（scheduler_mutations）、Q6（source_cards 所有权）两格当场定案；
- [ ] **上游一致**：与 ADR 0036/0037/0042、doc 41 §3 不变量无冲突；被否决路线（ADR §被否决）论证成立；
- [ ] **Step 1 六发现闭环**：每条有结构答复或明确排期（K6/K13/K14/D8/D9 + 切换异常条目）；
- [ ] **Step 3 边界清楚**：需要的 op 清单（配置区读、配置区写、只读 diff 候选）明确到「必须 / 可选」，编号从 41 起、只列不占；
- [ ] **Step 5 草图成立**：迁移短事务搬「三样」的列举无遗漏（映射→配置区、账本收敛、视图重建标志）；
- [ ] **量化门禁有钩子**：Q3 视图重建性能定标方式、K 矩阵进 Step 4 强杀测试的对应关系可执行。

评审记录（意见、修订、日期、参与人）回填本文件收据表；ADR 本体只改状态行与必要的决策修订。
