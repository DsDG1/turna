# Anki 集成重构文档（Turna）

> **这份文档是干什么的**：给第一次接触本目录的同学一份导读。它不是技术细节文档,细节在各 step 的子文件里。

## 1. 整件事用一句话说

Turna 是一个学外语（目标语：土耳其语）的手机 App。它要让用户能把自己在 Anki（一个流行的背单词 App）里做好的卡片组导入进来,变成 Turna 里的一个课程。整个 2026 年的工作就是把"导入 → 形成课程 → 删除 → 复习"这条链从一团乱麻的旧方案（v1）换成干净的、能稳定撑住大数据量的新方案（v2）。

现在 v2 已经能用,旧方案还在被拆。

---

## 2. 先认识一下背景

### 2.1 Turna 和 Anki 是什么关系

- **Anki** 是一个老牌背单词 App,全世界很多人用它。它的核心是"间隔重复算法":一张卡片,第一天答对就隔 1 天再考你,答对再隔 3 天……让你在快忘的时候被提醒,记得最牢。它的数据存在一个 SQLite 数据库文件里,叫 `collection.anki2`。
- **Turna** 是我们要做的产品,目标教土耳其语。它想复用 Anki 的卡片（用户可能已经做了几千张土耳其语卡片),也复用 Anki 的复习算法（这块 Anki 做得很好,我们没必要重做)。
- **集成方式**：用户在 Turna 里点"导入 Anki 牌组",选一个 `.apkg` 文件（Anki 的导出格式),Turna 把里面的卡片读进来,在自己的"课程树"里显示出来,然后用 Anki 自己的复习引擎（rslib,用 Rust 写的)来排期。

### 2.2 旧方案（v1）是什么样子

为了让 Turna 显示出这些 Anki 卡片,v1 干了这么一件事：把 Anki 的数据"翻译"一份到 Turna 自己的数据库里。一份课程树要在三张不同的表里各存一遍,卡片内容也要存三遍……理由是 Turna 想"不依赖 Anki 库也能用",但代价就是数据到处重复。

为了不让这些重复打架,v1 长出了一整套"对账"机制：每次启动比对三份数据一不一致,不一致就修,修不成就记日志让用户手动处理。

### 2.3 v1 的三大具体毛病

不是抽象的"数据冗余",是真机上的具体问题:

1. **删了牌组空间不回来**：用户删除一个导入的大牌组,界面说"删了",但手机存储没腾出来。原因是负责清垃圾的"维护任务"在 App 启动时被一行代码跳过了,只有去设置页点"优化数据库"才会跑。
2. **"清残留文件"是假的**：设置里有个按钮叫"删除残留文件",点了弹窗说"清理成功",实际一个字节都没动。代码里查的文件路径就不对。
3. **界面卡死**：删除或优化大数据库的时候,操作直接在界面线程上跑,App 会卡几秒到十几秒,期间什么都点不动,而且不能取消。

### 2.4 还有一个更隐蔽的雷

v1 的"导入→课程树"这条链,在测试里全是绿的,但**测试用的是假引擎**（测试环境拿假的程序模块代替真的 Anki 引擎)。假引擎恰好绕过了真引擎的状态检查,所以测试通过根本证明不了真机能跑。

2026-08-31 在真机上第一次测,果然一导入就报错（具体原因和修法见 [`step1.md`](./step1.md)）。

## 3. 新方案（v2）想干什么

### 3.1 核心想法

不再"翻译"数据。把 Anki 的官方数据库文件当成唯一的真相,Turna 只做两件事:

- **教学相关的事**：展示课程、播音频、记学习进度、出题目;
- **不再做的事**：存卡片内容、存牌组结构、存字段映射（以前 v1 都存了一份)。

这样同一份数据只在一份地方存,删了就是删了,不会"删了还在"。代码量预计能从约 33k 行降到约 15k 行——因为"对账"那一整套代码（约一半代码量）全部没了存在的理由。

### 3.2 v2 的具体目标

做完之后应该看到:

1. **导一个牌组,课程树就出现**,中间不再过 4 个数据库 38 张表。
2. **删一个牌组,存储真的回来**——自动清,不需要用户点"优化"。
3. **长操作能在后台跑**,用户能取消,界面不卡。
4. **所有"决策"（比如哪个字段是正面、哪个是背面）存在 Anki 数据库自己身上的配置区**——用户备份 Anki 库的时候这些决策也一起跟着走,不会丢。
5. **代码量减半左右**。

## 4. 工作是怎么组织的：六步走

整个 v2 工程被切成 6 步,顺序不能乱。每一步做完都有"过没过"的明确判断（看真机、跑测试、对收据),不是"代码写完了就算过"。

### Step 1：先修现有链的两个紧急 bug（2026-08-31 完成）

不写新代码,只修两个让当前 v1 在真机上根本跑不通的接线 bug。

**两个 bug 都是"漏了一句"导致的**：

- **Bug A**：导入卡片的代码拿了引擎之后直接调用"导入"接口,但忘了"打开库"这一步（就像你打开了 Word 但没新建文档就试图粘贴)。真机引擎要求"必须先打开库",假引擎不要求,所以测试全绿。修法：在两处漏掉的地方都补上"打开库"。
- **Bug B**：App 启动时本来该跑"清理垃圾"的维护任务,但代码里判断"引擎在不在",启动时引擎还没建,整个任务就被跳过。所以维护任务从来不会自动跑。修法：先查"有没有活要干",有活才去建引擎,没活就别建（不然会拖慢启动)。

**Step 1 还附带发现了一些真机问题**,都打包丢给后续 step:

- 导入完成后界面卡 5 秒被系统杀掉（结构性问题,Step 4 治本）
- 课程切换有时不灵
- 删除后清垃圾永远失败
- vivo 手机遇到 ANR 后日志就再也不出来（影响后续真机验证）
- 强杀 App 后某些设置会丢
- 假引擎测试为什么全绿：因为假引擎恰好绕过了生产代码漏写的那一行

### Step 2：写新架构的设计文档（2026-08-31 完成）

把 v2 的"长什么样"写进 ADR 0043（架构决策记录,这是仓库里固定格式的文档,每改一次架构就新开一份,编号递增)。

ADR 0043 包含：

- **9 条架构决策**：唯一真相源、决策存哪里、视图怎么重建、数据库表收敛、长操作后台化、文件日志、测试挂载点等
- **K1–K14 中断场景矩阵**：把"用户在各种时机把 App 强杀、操作系统重启、断网"等 14 种场景一一列出来,每种场景给出 v2 怎么扛的答案。这是评审的硬要求——任何一种"可能这样"但没说清楚的,评审就打回。
- **18 张旧表 → 5 张新表的去处清单**

评审流程：写了草案 → 评审人对照检查表一项项过 → 全过才标"已接受" → 才能进 Step 3。评审中关掉了几个开放问题（其中两个当时定不下来,后续在 Step 3/4 里给出答案)。

### Step 3：给底层桥补两个接口（2026-08-31 完成）

什么是"桥"：Turna 用 Dart 写,Anki 核心用 Rust 写,两者通过 FFI（一种让 Dart 能直接调 Rust 函数的机制)互相调用。已经有 40 个这样的接口（叫 op,即操作)。

Step 4 需要在 Anki 自己的配置区读写用户决策,但目前没有这种 op。所以 Step 3 加两个：

- **op 41（读配置）**：按名字读一个配置项,找不到或格式坏掉就返回"没有"
- **op 42（写配置）**：写一个配置项,要求 key 必须是 `turna.` 开头（防止误写 Anki 自己的配置),单事务保证（写到一半被杀进程也不会留下半截)

并把"接口协议版本号"从 1.11 升到 1.12。版本号同时改 4 处（Rust 常量、Dart 常量、文档、测试基准文件),任何一处不一致测试就挂——这个一致性检查是 ADR 里规定的纪律。

### Step 4：v2 完整链路落码 + 真机验证（2026-09-02 完成）

把 v2 的所有代码写出来,包含 8 个新文件 + 4 个旧文件的最小改动。功能上分三段:

- **写侧（导入)**:卡片从 .apkg 进来 → 进临时库预览 → 用户提交 → 决策写 Anki 配置区 → 账本登记 → 课程树视图重建 → 完成
- **读侧**:用户看课程树,数据从视图来;复习答题,数据还是从 Anki 库来
- **维护侧**:删牌组是"退役流程"——先标记 → 后台删引擎里的卡 → 收尾 → 清垃圾

加一个开关叫 `v2ImportChain`,默认关。开关的作用是:开了,新导入走 v2;不开,走 v1。这样 v1 和 v2 同时存在,可以灰度切换。

最后做真机强杀矩阵（K1–K14）:把 14 种"杀进程"场景在真机上一一过一遍,系统能不能自动恢复。

这一步详细记录在 [`step4.md`](./step4.md) 和 [`step4-c3-runbook.md`](./step4-c3-runbook.md)（真机矩阵操作手册)。

### Step 5：老用户数据迁移（2026-09-01 取消）

原计划：把已经在用 v1 的用户,数据自动从 v1 的"三份副本"迁到 v2 的"一份"。

**取消原因**：当前用户基数不大,放弃迁移成本可控;迁移本身是个大工程,会再拖时间;不做迁移 v2 也能用——只是老用户继续走 v1,新用户走 v2。

具体决策记录在仓库 ADR 里（编号见 ADR 0043 之后的下一份)。

### Step 6：删除旧代码,清场收尾（2026-09-04 代码侧完成）

代码侧已经做完（分支 `p1-dead-code-cleanup`,未提交）。包括：

1. **Catalog 数据库从 18 张表物理砍到 5 张**（v13 → v14,真正 DROP 13 张)
2. **course.db 从 11 张 anki 相关表砍到 2 张**（v23 → v24)
3. **分 4 阶段删旧代码**：旧投影流水线、Legacy 迁移模块、对账代码、过渡开关
4. **Guard 锁门测试**：写自动化测试,以后谁不小心把旧符号写回来,测试就挂

净删约 1.94 万行代码,完成度按代码已经 100%,剩 4 个真机冒烟测试要做（升级新包冷启动、导入新牌组、卸载牌组、检查修复中心）。
