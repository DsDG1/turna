# Anki 导入页 · 易用性设计

> 施工优先级以 [`official-anki-migration/31-anki-product-experience-plan.md`](./official-anki-migration/31-anki-product-experience-plan.md) 为准。
> Android 生产导入先有硬阻断（worker 未就绪 fail-closed、完成页无 summary、cutover 二次 Legacy parse），本文件的 A–F 是向导打通之后的易用性 backlog，不能单独当当前计划。
>
> 上一轮改造后页面 IA、文案、性能都到位了，这一轮专门谈**易用性**。
> 不再改信息架构，而是看用户从「打开页面」到「学完第一张卡」这整条路上，哪里还在绊脚。

---

## 1. 我们用 Nielsen 10 条做体检

针对 `AnkiImportPage`（5 步向导）逐条打分，挑出真正卡用户的几条：

| # | 启发式 | 当前现状 | 分数 |
|---|--------|----------|------|
| 1 | 系统状态可见 | 解析/导入时只一个 spinner + 一行文字，没分阶段、没 ETA | ⚠️ |
| 2 | 系统与现实匹配 | "笔记类型映射 / AI 智能识别 / SRS 调度" 等术语偏技术 | ⚠️ |
| 3 | 用户控制和自由 | 解析完成后没有"返回选文件"的入口，要重启 wizard | ❌ |
| 4 | 一致性 | 5 步用 stepper 之后，单步内的小组件风格已经统一 | ✓ |
| 5 | 防错 | 强制替换只加了 hint 文字，没有"二次确认"防手滑 | ⚠️ |
| 6 | 识别而非回忆 | 策略后果已加，但其它术语（智能分组、翻面卡）仍需猜测 | ⚠️ |
| 7 | 灵活高效 | 没有"记住上次选择"、没有快捷操作、没有拖拽 | ⚠️ |
| 8 | 极简 | 预览页已分组，但每节内仍偏密 | ✓ |
| 9 | 错误恢复 | 报错直接 `e.toString()`，用户看不懂 | ❌ |
| 10 | 帮助文档 | 没有任何 `?` 帮助入口 | ❌ |

**重点关注 1、3、5、6、7、9、10**——这 7 条是真正影响"用户能不能顺利完成一次导入"的地方。

## 2. 改进方向（按"用户感知收益 × 实施成本"排序）

### 改进 A · 进度分阶段展示（启发式 1）

**问题**：万级卡片导入要 30s+，用户看到的是"正在构建课程树…"一行字，不知道还要等多久、现在是第几步。**容易按取消键**。

**方案**：把导入过程拆成 4 个有名字的阶段，spinner 旁边画一个垂直小清单：

```
✓ 复制媒体文件
✓ 解析牌组
⟳ 构建课程树…
⏸ 迁移 SRS 状态
⏸ 保存元数据
```

已完成的对勾、进行中转圈、待办空心。阶段切换时还配一个 200ms 的轻动效。

**收益**：用户知道在做什么、还差多少。**明显降低误取消**。

**成本**：中。`AnkiDeckAssembler` 已经按阶段回调（copyMedia → assemble → migrate → save），只要把回调文案挂到一个新的 `_ImportStep` 枚举上。预估 200-300 行。

---

### 改进 B · "最近导入"快捷入口（启发式 7）

**问题**：用户重新导入同一份文件是常见操作（增量更新），但每次都得重新走系统选择器。

**方案**：在 Step 0（选文件页）底部加一个"最近导入过的牌组"区块，展示最近 3 条：

```
[icon] 土耳其语问候 · 234 张 · 2 天前
       来源: Anki/学习/sample.apkg         [重新导入]
```

点击「重新导入」直接走 `_proceedWithPath`。如果是同一个文件（hash 命中），UI 直接跳到 Step 2 预览页——不重新走解析。

**收益**：复访用户的核心路径从 5 步变 2 步（点卡片 → 看预览）。

**成本**：中低。需要存一个 `RecentAnkiImport` 表或 SharedPreferences 列表，已有的 `AnkiImportRecord` 表几乎够用，扩展一个 `displayName` 字段即可。

---

### 改进 C · 入库前最后确认（启发式 5）

**问题**：选了"强制替换"或大批量删除时，用户可能手滑。已经加了 hint，但**"提示"和"确认"是两回事**——Nike 不会因为 logo 是勾就相信你买了鞋。

**方案**：点击「开始导入」后弹一个 `BottomSheet` 二次确认：

```
┌──────────────────────────────────────┐
│  即将导入                            │
│                                      │
│  1,234 张新卡片                      │
│  56 张已存在（按「合并」处理）         │
│  4 个媒体文件                        │
│  预计创建 12 节课                     │
│                                      │
│  ⚠ SRS 状态与复习历史会保留          │
│                                      │
│  [取消]              [确认导入]       │
└──────────────────────────────────────┘
```

**何时触发**：
- 总是触发（不区分策略）——**入库是不可逆的**，多一步确认永远值得
- 危险策略（强制替换）文案加红、加 warning icon

**收益**：杜绝手滑。**对老用户可能略烦**，但可以用"3 秒内再次点击直接跳过"的方式做逃生通道（可选优化）。

**成本**：低。一个 BottomSheet + 一个新文案 key 集合。预估 100 行。

---

### 改进 D · 错误消息人性化（启发式 9）

**问题**：当前 catch 里都是 `_error = AppStrings.ankiImportFailed(e)`，渲染的是 `toString()` 出来的 Dart 异常名，用户看到的是 `Exception: Instance of 'FormatException'` 之类。

**方案**：建一个 `AnkiImportError` 分类 + 用户友好文案映射：

| 内部异常 | 给用户看 |
|----------|----------|
| `AnkiImportCancelled` | （回到 Step 0，不报错） |
| `OhosFilePickerInvalidExtension` | 「请选择 .apkg 或 .colpkg 文件」 |
| `FileSystemException` (权限) | 「无法读取该文件。请检查文件权限」 |
| `SqliteException` (DB 锁) | 「数据库忙，请稍后重试」 |
| `FormatException` (损坏包) | 「文件已损坏或不是有效的 Anki 牌组」 |
| 其它 | 「导入失败，请重试或换一份牌组」+ **附展开的详细错误**（折叠起来） |

**收益**：用户**知道出了什么事、下一步怎么办**。

**成本**：中低。在 `_executeImport` 和 `_parseFile` 的 catch 块里加 `on` 链分发。预估 50-80 行。

---

### 改进 E · 关键技术名词加 `?` 浮窗（启发式 2、6）

**问题**：「笔记类型映射」「AI 智能识别」「智能分组」「Cloze 填空」这些词不是所有用户都懂。

**方案**：在关键名词旁加一个 `?` 小图标，**点击**（不是 hover，因为是触屏）弹出一个小气泡：

```
? ←─ 点击后弹
┌────────────────────┐
│ 笔记类型是 Anki    │
│ 牌组里"卡的模板"   │
│ 的定义。比如       │
│ "单词卡" 模板有    │
│ 正面/背面/音标      │
│ 三个字段。         │
└────────────────────┘
```

**覆盖范围**（按价值优先）：
- 「笔记类型映射」— 1 句解释
- 「AI 智能识别」— 解释"AI 帮你猜题型，不是 AI 改你的牌组"
- 「Cloze 填空」— 1 句+例子
- 「翻面卡 / 词汇 / 表达」— 3 个一行说清差别
- 「SRS / 复习历史」— 1 句

**收益**：降低学习曲线，**对小白用户最值**。老用户可以忽略（小图标要克制）。

**成本**：中。需要一个通用 `HelpTip` 组件 + ~6 段简短文案。预估 100-150 行。

---

### 改进 F · 记住上次选择（启发式 7）

**问题**：每次导入都要选策略、选要不要导入学习进度。多数用户的偏好是稳定的。

**方案**：在 `SettingsProvider` 加一个 `AnkiImportPreferences`（或独立 SharedPreferences）：

- `lastStrategy: ImportStrategy?`
- `lastImportLearningProgress: bool?`
- `lastSmartGrouping: bool?`

进 Step 2 时优先用上次的选择，留一个"重置为推荐"的小链接。

**收益**：复访用户**少做 3 个选择**。**比改进 B 更轻**。

**成本**：低。SharedPreferences + 几行 initState 逻辑。预估 30-50 行。

## 3. 推荐的落地节奏

| 阶段 | 包含 | 估时 |
|------|------|------|
| 阶段 1（快速见效） | D 错误消息 + F 记住选择 | 半天 |
| 阶段 2（核心体验） | A 进度分阶段 + C 入库前确认 | 1 天 |
| 阶段 3（精打细磨） | B 最近导入 + E 名词解释 | 1-1.5 天 |

**阶段 1 性价比最高**——D 和 F 都是低风险小改动，但能立刻减少一半的"用户放弃/出错"。

**阶段 2 是质变**——A 和 C 直接改变了用户对导入过程的"信任感"和"掌控感"。

**阶段 3 看用户量**——B 和 E 对**新用户**价值大，**老用户**感知小。可以等数据看。

---

## 4. 不在范围

- 不重做向导结构（5 步不变）
- 不做后台导入（前台阻塞式更适合"我要立刻看到结果"的心智）
- 不做导入历史全表（只做"最近 3 条"）
- 不做 Onboarding 浮层（对新用户友好，但对老用户是噪音）
- 不动业务逻辑

---

## 5. 验证方式

- [ ] 选大文件 → 进度分阶段清晰可见，**用户能正确预测"还要多久"**
- [ ] 选"强制替换"策略 → 二次确认 sheet 出现，红色警告文字清晰
- [ ] 第二次导入同一文件 → 策略默认跟上一次一致
- [ ] 故意选一个 .txt 文件 → 报错文案是"请选择 .apkg 或 .colpkg 文件"，不是 `Exception: ...`
- [ ] 故意导入损坏的 .apkg → 报错文案是"文件已损坏或不是有效的 Anki 牌组"
- [ ] 点击"笔记类型映射"旁的 `?` → 弹出解释气泡

---

## 6. 风险

- 改进 A 依赖 `AnkiDeckAssembler` 的阶段回调，**已经存在**，风险低
- 改进 C 的二次确认可能让老用户嫌烦，**建议加 24h 内重复点跳过**（可选）
- 改进 D 需要枚举所有可能的异常，**做不到 100% 覆盖**——兜底用通用文案 + 折叠详细错误
- 改进 E 的 `?` 浮窗在 Step 2 密集布局中要小心不能挡内容
