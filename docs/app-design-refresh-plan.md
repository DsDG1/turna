# Turna 全 App 版面重设计与页面重构计划：湿地雾光

> 文档类别：架构与设计的提案附件。本文描述目标设计、实施顺序与验收方法，不声明任何页面已经完成翻新。
>
> 当前实现与能力边界只认 [项目指南](./project-guide.md) 和 [当前状态](./status.md)；行为约束见 [Agent 规范](../AGENTS.md)。本文涉及的设计调整在落地时更新项目指南；改变既有决策时另写 ADR，不以计划覆盖现有契约。
>
> 本轮交付是整套界面的重新设计计划。实施要求逐页重做信息层级、版面构图和页面呈现代码，使新旧界面具有明显的结构差异。视觉样稿、组件实现、资产制作与安装包属于后续阶段产物。

## 1. 目标与范围

### 1.1 翻新目标

**重新设计每个页面的完整版面，并按新设计重构页面呈现层，使整个 App 在构图、信息组织、交互区和视觉节奏上与旧版明显不同。**

「湿地雾光」提供新设计的品牌语言：湿地自然色、几何现代主义、背光雾面彩玻璃，以及适合持续学习的阅读秩序。现有功能作为重新设计的内容输入，旧页面的布局和组件排列不作为必须保留的设计前提。

重新设计同时完成以下工作：

1. 重建版面：重新决定首屏内容、主次关系、模块顺序、页面分区、对齐、密度与留白。
2. 重建视觉重心：为课程、作答、复习、词典、AI、个人与设置建立各自合适的构图。
3. 重建操作组织：重新安排主要操作、辅助入口、筛选、详情、反馈和返回路径的呈现。
4. 重建图形与组件：几何图形参与页面分区与内容组织，公共控件按新设计建立。
5. 重构页面代码：依据新结构拆分和组合 widget；保留业务接缝，替换限制新设计的旧视觉组件。
6. 完成全状态：将浅色、深色、高对比、大字号、加载、空内容、失败与能力受限场景纳入新布局。

### 1.3 实施边界

- 翻新以现有产品能力和真实数据为输入。课程内容、FSRS、学习结算、数据库格式与导入协议遵循原有契约；发现业务问题单独记录和处理。
- 记忆卡（Anki 牌组）在信息架构上独立于语言课程域：入口、列表与完成动作不进入课程管理，导入与复习功能保持原版（[ADR 0066](./decisions/0066-anki-deck-domain-independence.md)）。
- 全 App 设计覆盖记忆卡的宿主界面、工具栏、加载、失败、评分区和默认卡壳；用户导入的第三方 HTML/CSS 模板保留内容与交互保真。
- 品牌装饰使用几何图形。教学插图继续承担物体、场景与角色辨认的任务，遵循 [课程白板](../WHITEBOARD.md) 的内容路线。
- `tool/gui/` 是独立创作者工具。共享品牌色的对等关系继续维护，App 的玻璃材质和页面布局翻新不扩展为编辑器重做。
- 平台展示受现有能力开关约束；鸿蒙伴生版的 AI、跟读等边界见 [当前状态](./status.md)「鸿蒙三层口径」。
- 现有功能目的地、路由守卫和平台自适应返回行为继续有效；主导航的形状、位置关系、标签呈现、页面入口组织和次级导航可以重新设计。需要改变路由层级时，随设计说明用户路径与契约迁移，并记录必要决策。

### 1.4 每个页面必须达到的重设计深度

每页先从实际用户任务出发重新画线框，再进入视觉设计与实现。新旧对照至少说明以下维度如何变化：

| 维度 | 必须重新设计的内容 |
|---|---|
| 首屏与重心 | 第一眼看到什么，任务、标题、关键内容与主要操作各占多少空间 |
| 信息分组 | 内容如何合并、拆分、排序，哪些信息留在首层，哪些进入详情或辅助区 |
| 空间构图 | 页面分区、阅读轴线、对齐、疏密、大小关系、纵向与横向组合 |
| 交互区 | 搜索、筛选、作答、提交、揭示、反馈、工具和返回的具体位置与展开方式 |
| 视觉语言 | 几何图形如何与内容结合，文字、纸面、玻璃和信号如何建立层级 |

**验收时同时查看去除颜色、渐变和阴影的线框对比。内容分区、主次关系和操作组织仍须清楚体现新设计。** 仅改变色值、圆角、阴影、图标或间距，不能计为该页面已完成重设计。

业务上需要保持稳定的结构单独列明，例如第三方原卡内容、系统文件选择器和权限弹窗。它们的宿主与前后流程仍属于页面重设计范围，不要求为了差异破坏平台或内容契约。

## 3. 品牌手册：湿地雾光

### 3.1 风格总述

Turna 的视觉从湿地清晨取色：水面带蓝的青、芦苇透亮的绿、岸边温暖的沙，以及陶土中沉静的橙棕。大面积白色提供空气与光照的空间，水鸭青建立重心，浅绿和天光蓝舒展画面，沙色与陶土色在局部带来温度。

图形以圆、半圆、圆弧、矩形和拱形为基本元素，通过比例、切分、重复与叠放形成秩序。构成借鉴包豪斯的几何语言，材质则采用细磨彩色玻璃的柔和质感：轮廓清楚，内部透光，边缘轻微积色。

光像从玻璃背后缓缓透过，在颜色内部形成宽而柔的亮部。玻璃上缘薄透，下缘稍沉，投影带少量冷色并柔缓地落向纸面。整套界面呈现安静、温暖、清透、有秩序的气质，支持长时间阅读与反复练习。

「湿地雾光」是本项目的品牌方向名称；几何现代主义与雾面彩玻璃是对其构成和材质的说明。

### 3.2 色彩角色

| 基色 | Token / hex | 设计用途 |
|---|---|---|
| 水鸭青 | `brandTeal` / `#1F727E` | 主按钮、选中、当前学习路径与关键可操作内容 |
| 浅水鸭青 | `brandTealLight` / `#2F7F8E` | 主按钮受光端与同族层次 |
| 深水鸭青 | `brandTealDark` / `#145A64` | 按下、深强调与需要更高可见度的状态 |
| 芦苇青绿 | `brandReed` / `#78C7B8` | 小面积高光、几何图形亮部与深色强调 |
| 天光蓝 | `brandSky` / `#4A95A8` | 听力、信息与次级冷色 |
| 陶土橙棕 | `anatolianClay` / `#B85C3F` | 完成、成就、暖色标记 |
| 暖沙米色 | `warmSand` / `#EAD9B8` | 浅暖表面、几何图形暖部与成就的柔和衬底 |
| 深水蓝 | `brandNavy` / `#19324A` | 视觉锚点与阴影染色 |
| 雾青灰 | `glassNeutral` / `#8CA0AB` | 默认玻璃与弱强调表面 |
| 白与中性黑灰 | `scaffoldBackground` / `darkScaffold` 等 | 画布、阅读与页面层级 |

用色方法：

- 保留约 70% 中性、20% 湿地冷色、10% 暖点缀的总体构成指导；按整屏视觉重量理解，不要求每张卡都凑齐三类颜色。
- 「淡绿、淡棕橙」由现有青绿、暖沙和陶土基色的材质派生色表达。基色承担识别，浅色面承担氛围。
- 普通正文使用文字 token。浅绿、淡沙与玻璃高光主要服务图形和表面。
- 品牌暖色与反馈语义保持分工：正确反馈沿用 `success`，错误沿用 `error`，待办或警告沿用 `warning`；成就沿用 clay，连胜沿用既有 streak 语义。
- 玻璃派生色统一由主题计算，页面不另写品牌色、任意透明度或局部混色公式。

### 3.3 几何图形系统

建立可复用的品牌图形语法：

| 图形 | 品牌联想 | 合适位置 |
|---|---|---|
| 圆与半圆 | 水面、光斑、起点与积累 | 练习入口、完成页、空状态的小型主图 |
| 平行弧线 | 涟漪、反复练习与回忆 | 复习、听力、学习记录的装饰 |
| 拱形与竖向矩形 | 旅程、门、向前展开的空间 | 章节头图、课程切换、启动构图 |
| 交叠色片 | 知识之间的连接 | AI 与工具入口的辅助图形 |
| 少量斜切与留白 | 节奏与方向 | 重点模块的局部构成 |

制作约束：

1. 一幅图围绕一个主形组织，辅形控制在少量；手机小尺寸下仍能辨认轮廓。
2. 图形可以超出局部插画框裁切，正文和操作区域拥有完整留白。
3. 同一图形提供浅色、深色和简化版本；高对比时依靠轮廓与形状表达。
4. 基础几何、图标和可编辑插图优先用代码或兼容 `flutter_svg` 的 SVG；必要栅格资产单独记录尺寸、用途和导出规格。
5. 教学图像先保证语义可辨认。课程要求的茶杯、咖啡杯和角色形象不以抽象品牌装饰替代。
6. 现有鹤形象、应用图标和启动标识在 P0 一起清点；保留识别特征，通过轮廓、色彩和光感统一。重绘数量由资产清单确定。

### 3.4 材质与光照

| 表面 | 视觉目标 | 使用位置 |
|---|---|---|
| 纸面 | 干净、稳定、薄；以排版和中性细边分组 | 课程旅程、词典、成组统计、密集列表、弹层正文 |
| 雾面彩玻璃 | 低彩度淡彩、宽亮部、轻微积色边与柔影 | 独立练习工具、复习主卡、完成重点、个人概览 |
| 扁平控件 | 清楚的填充、描边、按压与焦点 | 按钮、选项、词块、筛选、设置行 |
| 磨砂浮层 | 能感知背后内容，前景文字稳定可读 | 现有底部胶囊与 SnackBar 等已获准的浮层 |

光照校准按以下顺序完成：

1. 固定纯白画布，比较 neutral、teal、sand、clay 四类材质样板。
2. 调整亮部宽度与明暗过渡，使颜色呈现柔和透光；保留明确边界和正文对比。
3. 调整投影距离、扩散与彩度，使其呈现轻微悬起的厚度；避免底缘成为整齐的多层色带。
4. 同一参数在浅色与深色样板中核对，再进入长列表检查累计视觉重量。
5. 有必要改变浓度、投影或层级语义时，集中修改主题参数并记录决策影响。

背光是视觉目标，由轻量渐变、明暗和边缘关系表达。静态内容卡继续使用既有 `GlassSurface`，不逐卡增加实时背景模糊、动态折射或着色器依赖。

深色画布沿用中性黑灰，颜色集中在对象和信号上；玻璃通过深色基面、微亮边和柔和受光分离。高对比模式沿用 `GlassMode.off` 的撤回逻辑，操作和阅读依靠现有高对比主题。

## 4. 布局、排版与密度

以下数值是翻新样稿的起始设计目标，P1 用真实内容校准，随后集中成 token。

### 4.1 全新构图体系

设计采用明确的文字层级、主辅尺度对比、宽松分区和局部几何构图。页面根据任务选择空间组织，避免所有功能都排成同样的标题加等大卡片。

| 版面类型 | 组织方法 | 主要页面 |
|---|---|---|
| 学习旅程 | 当前章节作为开篇，下一步作为重点，其余课时形成连续目录 | 课程主页、章节选择 |
| 沉浸作答 | 顶部轻量上下文，中间大尺度学习内容，下方独立作答与阶段操作 | 课时、复习、每日挑战 |
| 今日任务台 | 一项主要任务与有顺序的待办列表，工具放入次级索引 | 练习入口、复习入口 |
| 内容阅读 | 搜索或目录作为起点，正文连续展开，工具贴近内容 | 词典、阅读、解释、说明文档 |
| 学习档案 | 一段概览与纵向记录相连，局部数字和图表解释变化 | 个人、成就、进度、洞察 |
| 步骤流程 | 任务标题、当前步骤、工作区和明确的下一步构成一条路径 | 导入、映射、适配、备份恢复 |
| 偏好目录 | 分类索引、分区标题和直接可读的表单关系 | 设置、API 配置、诊断 |

同类页面共享阅读和操作规律，具体内容仍需逐页线框。每页明确自己的首屏重心、模块顺序和动作位置，不直接把旧容器替换成新版容器。

### 4.2 栅格、形状与空间

- 重新建立页面栅格：手机从 24 的主边距与 16 的紧凑内容边距起步，围绕内容重要性设置 8 / 12 / 16 / 24 / 32 / 48 的空间节奏。
- 重点区域采用明显的尺度变化，例如大章节标题与紧凑课时目录、大目标词与辅助例句、大待办数字与细列表。避免每块内容获得相同体积和强调。
- 几何图形可与章节标题、数字和图像形成局部不对称构图；正文保持稳定阅读轴线，主要操作容易定位。
- 密集内容通过段落、栏位、序号、分隔线和背景留白组织。卡片只在独立对象确实需要边界时使用。
- 圆角、边框和控件尺度依据新版样稿建立，统一写入主题；当前数值作为兼容资料，不要求沿用旧卡片外形。
- 所有滚动页重新计算系统安全区、主导航覆盖范围与键盘占位；导航的具体形态由新版外壳设计确定。

### 4.3 字体与文字

沿用系统字体，提供主题内统一的文字角色：

| 角色 | 起始字号 / 字重 | 用法 |
|---|---|---|
| 页面标题 | 28–36 / 600–700 | 一级页面、章节开篇与重要完成标题；窄屏和长标题按内容换行 |
| 区块标题 | 18–20 / 600 | 页面内分组 |
| 卡片标题 | 16–18 / 600 | 入口、设置组与结果标题 |
| 正文 | 16 / 400–500 | 说明、释义、反馈与可持续阅读内容 |
| 辅助信息 | 13–14 / 400–500 | 时间、来源与次要统计 |
| 按钮 | 16 / 600 | 主要操作 |
| 学习题面 | 20–28，随内容长度适配 | 目标词句；阅读文章另用正文角色 |
| 重点数字 | 28–36 / 600–700 | 今日待复习、完成概览等少量位置 |

正文行高以 1.45–1.65 作为样稿起点。用中土混排、土耳其语变音字符、长单词、长子课名和多段反馈检查，不以缩小关键文字解决拥挤。

普通字号与 200% 文本缩放共同设计；卡面单独字号偏好继续作用于原有范围。统计数字扩大时，标签与单位仍可读、可换行。

### 4.4 宽度适配

| 可用宽度目标 | 布局方向 |
|---|---|
| 小于 600 逻辑像素 | 手机单栏；次级信息顺排，底部操作考虑键盘与安全区 |
| 600–839 | 居中主内容；工具网格可扩列，正文保持舒适宽度 |
| 840 及以上 | 列表与详情在合适场景并排；学习题面保持单一阅读重心 |

断点按可用空间和内容验证，复用 `LayoutBuilder`、`MediaQuery` 与现有 `AdaptiveCardGrid`；阅读与练习主列从约 640–720 的最大宽度开始校准。宽屏设计覆盖现有客户端能力，不新增平台支持声明。

## 5. 公共组件与交互契约

### 5.1 组件目录

先从新版页面线框提炼组件，再决定复用、改写或替换现有实现。数据接缝、无障碍能力与可靠的底层交互可以复用；旧组件的外形、组合方式与默认尺寸均可重建。跨功能组件进入 `lib/views/widgets/`，功能私有组件留在对应功能域；已有 `widgets/` 目录按原路径维护。

### 5.2 状态设计

每种可操作组件按适用情况提供默认、按压、键盘焦点、选中、禁用、加载、成功和错误样式。状态通过文字、图标、边框或布局共同表达，颜色承担辅助信号。

- 主要触控区域以至少 48×48 逻辑像素为设计目标；图标可保持较小，点击范围独立扩大。
- 主按钮在同一任务区保持单一视觉重心。危险操作使用明确动作词，确认与取消位置在同平台内一致。
- 提交、评分、导入与恢复的进行中状态接现有业务状态；重复操作控制沿用服务与 controller 契约。
- 长按提供补充信息；已有短按主路径保持直接可用。重要内容同时给屏幕阅读器或可发现入口。
- 错误在出错位置说明原因与下一步；一次性结果使用 SnackBar，可恢复加载失败保留页面错误状态。
- 触感与音效尊重 `sensoryReduce`，动画尊重 `reducedMotion` 和系统禁用动画设置。

### 5.3 动效

依据新构图设计微反馈、展开、内容替换与反馈揭示。`lib/core/motion.dart` 中 `TurnaMotion` 的时长和曲线可作初始参考，新版节奏在样板中统一校准，参数继续集中在公共层并同步调用方。

只在状态变化时运动：导航选中、展开、选项反馈、进度、完成标记。静止页面应能停止持续绘制。减少动态效果时保留最终状态和操作反馈，去掉非必要位移与弹性。页面间转场继续使用平台自适应路由。

### 6.2 每页独立交付的设计单

页面清单的每一项都建立独立设计单，最低包含：

1. **页面身份**：实际页面 / 路由 / 弹层、入口、平台、主任务与返回位置。
2. **现有结构**：旧版截图和线框，标明当前模块、顺序、主次与动作。
3. **新版线框**：新分区、阅读轴线、模块顺序、主操作与次操作；标明首屏和滚动后的内容。
4. **版面变化说明**：逐项说明哪些区块重新合并或拆分，视觉重心、密度和交互组织如何改变。
5. **视觉稿**：真实内容、字体、几何图形、材质与状态；附深色和适用适配变体。
6. **实现接缝**：业务状态来源、要复用的逻辑、要重构的 widget 和要替换的旧组件。
7. **验收对照**：同设备尺寸和内容下的新旧截图，以及线框、操作与状态检查结果。

分类页、详情页、表单页、空状态和全局弹层均有独立处理。共享模板可以减少重复制作，但每个页面仍需核对实际内容与结构；代表样稿不能替代其余页面的设计交付。

### 6.3 信息架构的调整方式

功能可达性保持完整，呈现方式允许重组：入口可以重新归组，统计可以从顶栏移入页面，次要说明可以进入可发现详情，表单可以按任务拆分或合并步骤。

每次重组须同时交代旧入口到新入口的对应关系、主任务完成路径、返回与状态保留、辅助技术顺序和已有路由守卫。对需要的路由变动同步注册与代码生成；不以保留旧 widget 树为限制新设计的理由。

## 7. 学习题型的专项设计

### 7.1 题型分组

实际题型以领域模型和 renderer 注册为准，逐项映射到以下呈现规则：

| 学习任务 | 布局与控件 | 专项验收 |
|---|---|---|
| 认识词汇与图像回忆 | 大词头与发音构成主区，图像和例句形成辅区；揭示后展开释义段落 | 图像比例、词句点读、答案揭示、长释义、大字号 |
| 单选 / 多选 / 听选 / 判断 | 大题面与紧凑答案区形成尺度差；文本选项采用编号行，图像选项采用网格，多选显示操作提示 | 文字换行、多选数量提示、颜色之外的正误信号、重复点击 |
| 填空 / 翻译 / 拼写 / 听写 / 简答 | 上方保留完整上下文，下方是明确书写区；输入后将自己的答案与正确表达分区呈现 | 土耳其语字符、输入法组合态、键盘遮挡、长答案与纠错 |
| 排序拼句 | 题面、可换行答案槽与下方词库形成三段；词块点击和拖动共用同一排序状态 | 重复词、长句换行、移除与重排、辅助技术替代操作 |
| 纯听与对话 | 播放主控形成视觉中心，角色与句段沿纵向展开；听辨任务的选项占独立下半区 | 播放 / 暂停、加载失败、角色区分、听力内容揭示时机 |
| 阅读理解 | 文章采用连续阅读版面，问题区明确接续；宽屏允许文章与问题并排，窄屏提供可发现的回看入口 | 长文章、选择 / 判断 / 简答、文字缩放与滚动 |
| 跟读 | 示例句、示范播放、录音主控与词面结果形成清晰的阶段构图，权限与不可用提示原位呈现 | 权限、识别不可用、失败重试、降级为听示范的路径 |
| 记忆卡 | 重建宿主的上下文、卡面可用空间与底部揭示 / 评分区，保留原 HTML 内容 | HTML 与媒体保真、卡面字号作用域、评分契约 |

### 7.2 课时页面的共同交互骨架

共同骨架约束退出、阶段和主操作的位置逻辑；具体题面与作答区按第 7.1 节分别重画，不要求所有题型共用同一张大卡和同一组垂直间距。

1. 顶部：退出、当前进度与必要上下文；统计以学习决策需要为限。
2. 内容：任务说明、词句 / 图像 / 文章 / 音频主体。
3. 作答：选项、输入、词块或回忆操作。
4. 反馈：结果、正确表达、简短解释与已有 AI 辅助入口。
5. 底部：当前阶段的主要操作，随键盘与安全区调整。

题目切换时保持操作区稳定；反馈导致内容增长时允许自然滚动。答案、解释与正确性提示的出现时机沿用教学与判分规则。

## 8. 无障碍、性能与平台

### 8.1 设计验收目标

- 普通正文对比度以至少 4.5:1 为目标，大字与关键图形以至少 3:1 为目标；高对比模式单独核对文字、控件边界与焦点。
- 200% 文本缩放下，核心任务可完成；重要题面、答案、主要操作与错误说明不得被截去。
- 屏幕阅读顺序与视觉顺序一致；图标按钮有名称、状态和动作；纯装饰图形退出语义树。
- 触屏、键盘与屏幕阅读器都有可完成主任务的路径；拖拽和长按有可发现替代操作。
- 文字和卡面字号偏好保持原有作用域，减少动态效果与感官降低模式真实生效。
- 小屏、横屏、底部手势区、键盘和长文本共同参与布局验收。

这些是本次翻新的内部验收目标，最终以组件、实机与辅助技术操作结果核对。

### 8.2 性能与生命周期

- 用同一设备、同一构建模式、同一内容集比较翻新前后的启动、滚动、题目切换和长列表。
- 60Hz 设备以约 16.7ms 帧预算检查明显卡顿；其他刷新率按对应预算分析。记录 UI / raster 慢帧与可感知停顿，发现问题定位后再增加特效。
- 列表沿用懒加载，Tab 沿用首次访问构建、访问后保留状态、隐藏时停用 ticker 的策略。
- 静止页无非必要持续动画；卡片静态材质不引入逐项背景采样。
- SVG、图片与媒体给出适当尺寸和缓存；图片缺失不挤坏题面和操作区。
- App 从后台恢复、主题切换、字号切换后，滚动位置、输入与会话状态遵循原有规则。

### 8.3 平台处理

Android 与 iOS 采用共同品牌语言，保留各自返回、输入法、安全区和路由手感。Web 与桌面只对现有可运行路径做布局核对。

鸿蒙伴生版使用相同设计 token 和适用页面，入口与受限说明服从实际能力。平台判断继续走 `isHarmonyOsTarget`；构建与 SDK 使用按 [鸿蒙构建说明](./ohos-build-setup.md) 执行，不能用界面翻新推断能力已验收。

## 9. 实施顺序与阶段交付

依赖顺序：**P0 逐页清点与旧版结构 → P1 全页面线框与核心视觉稿 → P2 新版组件系统 → P3 重构学习闭环 → P4 逐页重构其余功能域 → P5 全模式与边缘状态 → P6 新旧差异审查与交付。**

工作顺序始终是任务分析、信息重组、线框、视觉稿、页面代码重构、状态与交互核对。每阶段交付设计完整的小范围结果；后续发现共性问题时回到公共组件修正。以下是计划工作项，不是当前完成状态。

### P0：页面、状态与资产清点

**任务**

- 从路由、主 Tab、条件入口、深链和弹层调用建立页面清单，对照 R01–R18 逐项归属。
- 记录每项的入口、平台、主任务、实际状态来源、共享组件与私有组件；识别生产页面、诊断页和无入口存量页。
- 为每个页面抽取旧版线框，标明首屏、模块顺序、分组、交互区与可重新组织的部分；分开记录业务契约和视觉惯例。
- 在实际运行环境采集主要用户路径的浅色 / 深色截图；固定内容与主题，补充小屏、200% 字号和键盘场景。
- 清点图标、鹤形象、应用图标、启动图、教学插图、分享卡与空状态资产。
- 分类记录现象：层级、密度、材质、反馈、适配、状态遗漏。每项附具体页面和触发条件，不预设所有页面都有同一种问题。

**产物与退出条件**

形成完整页面覆盖表、逐页旧版结构、资产清单、可重复截图场景和带优先级的问题列表。路由、主 Tab、平台条件入口和全局弹层均有归属；截图注明构建、设备、主题、内容与触发步骤。一次性原始调查材料保留在交付记录或版本历史，不另写成活文档。

### P1：全页面线框与核心视觉定型

**任务**

- 将第 6 节蓝图展开为每个实际页面的新版线框。重新安排首屏、内容分组、模块顺序与操作区，并逐页说明相对旧版的结构变化。
- 将本计划第 3–5 节整理为可执行的品牌与界面样板：栅格、尺度、色彩、形状、材质、排版、图标、动效。
- 做 neutral / teal / sand / clay 材质对照，确定高光、厚度、投影与纸面的相对关系。
- 制作课程主页、单选题、带键盘输入题、练习任务台、正式复习、设置目录六类核心视觉稿，建立明显区别于旧版的整套版面语言。
- 同时提供代表样稿的深色版，以及至少一组 200% 字号和高对比样稿。
- 用实际课程标题、真实土耳其语例句、实际队列数据和现有功能入口填充；分别展示默认、空、加载与失败的适用状态。
- 将其余页面线框归入合适的版面类型，列出专属布局需求。进入对应页面实现前补齐视觉稿与状态，不用六类核心样稿代替全部页面设计。

**产物与退出条件**

形成全页面新版线框、逐页结构变化说明、品牌规则与六类核心视觉稿。去除颜色和材质后，核心版面仍能明确区分新旧。每个页面有新的空间结构，后续可以据此完成视觉稿和实现。需要改既有决策的部分，给出变化范围和理由，并在实施前形成对应 ADR。

### P2：建立新版主题与组件系统

**任务**

- 根据新线框与视觉稿建立文字、间距、容器、边框、投影与状态参数，统一放入 core 的主题与视觉 token；保留品牌 hex 和语义色角色。
- 重建页面骨架、导航、目录行、任务区、作答区、阅读区、步骤区与表单分区。对 `GlassSurface` 等底层能力做适配，对限制新布局的组件改写或替换。
- 按实际需求处理 `SoftCard`、设置 primitives 和选项组件；拆除不再承担职责的视觉包装，避免旧布局通过兼容组件继续进入新版。
- 为组件提供可交互预览场景，展示不同内容长度、主题、字号与状态；复用仓库可用的预览设施，必要时按现有 Flutter preview 规范建立。
- 将全局反馈、空状态、错误与弹层整理成一致的结构；先完成组件，再让页面消费。

**产物与退出条件**

形成新版主题、页面框架、公共组件与状态样板。组件能够表达 P1 的新分区与比例，旧页无须原位逐卡替换才能使用它们。无障碍回退、点击反馈和文字布局可在样板中检查。

### P3：按新设计重构学习闭环

**任务**

- 按新版线框重构全局外壳与导航，再依次重构课程目录、章节切换、课时骨架、每个题型和完成页的 widget 结构。
- 先打通「打开 App → 找到下一子课 → 进入 → 作答 → 查看反馈 → 完成 → 返回课程位置」。
- 覆盖全部现有 renderer，核对显示与提交时机、输入、音频、跟读、阅读和记忆卡宿主。
- 对齐进度、退出确认、奖励展示和结算结果；页面显示的奖励与进度来自真实结果。
- 为每页保存旧版、新版线框和实现对照；组件接入和参数变化不单独计为页面设计完成。

**产物与退出条件**

学习主线的每个页面都有清楚的新旧版面差异，并可完整操作。默认状态和异常状态使用同一设计体系；子课独立会话、课级结算、已完成与解锁的原有语义保持可辨认。小屏与键盘场景可完成真实课时。

### P4：逐页重构其余功能域

按以下依赖顺序推进。每个实际页面分别完成第 6.2 节设计单、视觉稿与呈现层重构，逐页核对入口、内容、操作、反馈和返回路径：

1. **练习与复习**：练习入口、各队列、每日挑战、统一复习、语法、错题与弱词、完成与来源详情。
2. **词典与数据**：搜索、词条、点读、进度、洞察、图表与个人统计共用的数据展示组件。
3. **记忆卡**：导入、预览、映射、适配、完成、浏览、统计、修复与复习宿主。
4. **AI**：功能入口、练习库、生成、运行、聊天、诊断、保存、教材导入与 API 配置。
5. **个人与设置**：身份、成就、头像环、分享卡、设置全部分类、备份、课程更新、诊断、关于与许可。
6. **全局临时表面**：横幅、提示、退出确认、选择器、底部弹层与 SnackBar，复核所有调用点。

**产物与退出条件**

R01–R18 中每个实际页面与浮层均完成版面设计和重构，覆盖表逐项对应到设计稿与实现。详情、表单、长列表、工具、说明、空状态与失败页同样通过结构差异核对。无生产入口的页面有明确处置，保留页面仍可读和可操作。

### P5：主题、适配、辅助技术与性能收口

**任务**

- 按第 10 节验收矩阵补齐深色、高对比、200% 字号、减少动态效果、屏幕阅读器与键盘路径。
- 核对窄屏、宽屏、横屏、输入法、长标题、长文章、大数据量与媒体失败。
- 核对 Android、iOS 和现有其他平台的入口差异、返回、安全区及宿主视图。
- 同设备前后比较滚动、启动与题目切换，修复明显帧耗、过度阴影与多余重建。

**产物与退出条件**

核心任务在目标布局和无障碍模式下可完成。性能退化有定位与处理结论；构建失败和缺少设备证据按实际情况报告，不以截图替代运行结果。

### P6：逐页差异审查、视觉资产与整包交付

**任务**

- 完成应用图标、启动、几何装饰、空状态、成就重点图和分享卡所需资产；与课程教学资产分别维护。
- 对覆盖表进行逐页新旧审查：同内容、同尺寸比较截图与线框；仍沿用旧内容分区、旧模块顺序和旧操作组织的页面回到设计阶段处理。

- 按目标平台构建安装包，使用当前版本配置；交付可安装产物、代表截图、品牌规则和实际限制。

**产物与退出条件**

翻新包可构建，每页有可复现的操作路径与版面对照。全部页面达到逐页重设计深度；系统与原卡保真等约束例外有具体说明。平台状态、测试状态和未完成项分别如实说明，剩余阻断项不得藏在“视觉完成”表述中。

## 10. 验收矩阵与完成定义

### 10.1 逐页版面差异验收

每个页面都进行以下核对，覆盖表中的“完成”必须对应具体页面与设计单：

| 核对 | 通过条件 |
|---|---|
| 首屏构图 | 主任务与视觉重心经过重新安排，标题、主要内容、辅助信息和操作比例体现新版设计 |
| 分组与顺序 | 能具体说明内容如何重新组织，信息层级和阅读路径如何变化 |
| 交互组织 | 作答、筛选、提交、揭示、反馈或管理操作的位置与呈现方式按该页面任务重新设计 |
| 去材质线框 | 去除颜色、高光和阴影后，新旧结构仍有明显区别 |
| 实现对应 | 真实运行界面达到设计稿的版面，而非只替换装饰参数或外层容器 |
| 任务完整 | 原有实际功能可达，数据与阶段正确，改版后核心任务依然清楚可完成 |

仅换色、换图标、调圆角、加玻璃、改间距或给旧组件换名字，均不能作为页面重设计的完成依据。差异以构图和任务组织说明，不设缺乏依据的“视觉相似度百分比”。

### 10.2 代表场景

| 场景 | 必查结果 |
|---|---|
| 首次启动与进入课程 | 信息清楚，播种与失败有状态；无无意义等待动画 |
| 课程树多层展开 | 子课标题可读，当前点清楚，完成与锁定能区分，返回位置正确 |
| 一个真实课时的完整过程 | 题面、输入、音频、反馈、下一步与完成连贯，进度和奖励正确显示 |
| 正式复习 | 原卡内容与媒体保真，答案与二档评分清楚，提交和结束行为一致 |
| 无待复习与无内容 | 解释当前状态，提供实际可用的后续操作 |
| 错题、弱词与图表 | 内容和时间窗能理解；少量数据和长数据可读 |
| 搜索词条 | 输入、无结果、点读和长释义完整，键盘不遮挡关键操作 |
| 文件导入与修复 | 各阶段状态真实，取消、失败、重试和完成有清楚路径 |
| AI 配置与生成 | 未配置、生成中、取消和失败可处理；能力受限平台不暴露不可用入口 |
| 备份与恢复 | 进度与互斥状态可理解，危险操作确认清楚 |
| 设置和静态长文 | 200% 字号、控件、链接、许可与长日志均可使用 |

### 10.3 模式覆盖策略

- 每个页面检查浅色、深色和正常字号下的主要内容与适用空 / 错误状态。
- 学习、复习、搜索、导入、设置和备份等核心路径检查高对比、200% 字号与屏幕阅读器。
- 公共组件检查四套主题、全部支持状态与长内容；页面再补齐各自的特殊布局。
- 小屏与常规手机覆盖主路径；宽屏选择列表、内容详情、阅读与工具网格等代表布局，发现通用问题后回到组件修复。
- 键盘、权限、离线、文件损坏和媒体缺失按功能适用性采样，不把不相关状态机械塞进每页。

### 10.4 完成定义

全部满足后才可称为「全 App 翻新完成」：

1. 页面清单中的所有实际页面、平台分支和公共浮层均有新版设计单、线框、视觉稿与实现对照；保真和系统约束例外单独列明。
2. 每页通过第 10.1 节的结构差异验收。公共主题调整不替代逐页版面重设计，代表页完成不代表其余页面完成。
3. 新版构图、排版、组件、材质和状态形成共同设计语言，各功能根据任务采用自己的页面结构。
4. 品牌几何图形、应用图标、启动与分享等已列入范围的资产完成所需变体和落位。
5. 学习、复习、搜索、导入、AI 适用路径、个人与设置能完成实际任务。
6. 深色、高对比、大字号和辅助技术不因改版丢失信息与操作。
7. 现有分层、平台、路由、术语、学习结算和原模板保真契约继续成立；设计引起的必要路由调整已同步实现和说明。
8. 目标包构建与可执行的人工检查有真实结果；缺少平台设备的项明确保留为待验证。
9. 已授权的自动验证执行完成，已知基线与新增问题区分清楚；未执行的检查明确说明。

## 11. 代码组织与验证纪律

### 11.1 实现落点

- `lib/core/`：主题、视觉与动效 token；公共代码不得依赖页面。
- `lib/views/widgets/`：跨功能渲染与交互组件。
- `lib/views/<feature>/components/`：新建的功能私有组件；存量路径按现有结构维护。
- `lib/l10n/app_strings.dart`：界面文案；用户可见产品术语使用「记忆卡」，许可与内部契约遵循既有例外。
- `lib/routing/`：必要的路由注册与守卫；设计调整不得在页面绕开现有路由系统。
- `assets/`：按既有资产结构与实际用途落位，新增目录在实施时登记并核对加载。

页面按新版分区重构 widget 树，必要时替换布局组件、拆分私有组件和提取新的跨域组件；controller 与 application 接缝保持明确。页面继续通过 application 门面或 domain 仓储接口消费数据，不在页面直接取得 DAO、数据库或 LLM SDK。新页面使用 `*_page.dart`，存量文件不为翻新顺手改名。

### 11.2 构建与检查

- 本计划编写阶段不执行 Flutter 分析、测试或构建。实施阶段默认按 [Agent 规范](../AGENTS.md) 构建、出包、人工查看；测试只在规定触发条件下执行。
- 用户明确要求验证、报告回归需要定位，或实际修改测试断言时，执行 `flutter analyze` 与 `flutter test --exclude-tags golden`。
- 涉及代码生成注解时按仓库规定运行 `make gen`；涉及鸿蒙时遵循 fork SDK 约束。
- 涉及 visual golden 的变更，先以实际界面和目标样稿确认预期，再在用户要求相应验证时定向比较；更新图片需能解释实际设计差异。
- 有测试数量变化时按规则前插更新 [测试基线](../test/BASELINE.md)。现有失配依该文件处理，不以批量重录掩盖无关变化。
- 品牌、玻璃、路由、分层、术语与文档现有契约均需遵循；验证未运行不改变其约束效力。
- 视觉问题用截图和触发步骤核对，交互问题用真实操作核对，平台支持用实际构建与设备结果核对。

## 12. 风险与处理方式

| 风险 | 处理 |
|---|---|
| 实施退化为全局主题换肤，旧版结构完整保留 | 每页先交新版线框，P3 / P4 按设计单重构，P6 做去材质的新旧结构审查 |
| 只重做主入口，二级页与弹层遗漏 | 页面清单按实际页面与浮层登记，页面族和代表样稿不代替逐项完成 |
| 为追求差异增加绕路、隐藏功能或无意义装饰 | 同时核对主任务、可发现入口、返回与状态；几何构图服从可读性与操作 |
| 只统一了材质，页面层级和任务仍不清楚 | P1 同时做布局、排版、动作和状态；P3 用完整学习闭环检验 |
| 全屏玻璃造成密度高、边缘厚和阴影累积 | 严格区分纸面、玻璃对象与控件；在长列表中校准视觉重量 |
| 淡色降低文字与状态辨识 | 文字用语义 token；重要状态加入图标、标签与边界；高对比独立核对 |
| 多功能域各自微调导致风格再次分叉 | 公共问题回到主题和组件修正，页面保留内容差异 |
| 视觉调整损伤学习流程或第三方卡片 | 保留 controller 与呈现契约，以真实课时、原模板与媒体核对 |
| 主题或组件改动影响大量页面 | 先样板，再学习主线，再逐域替换；每阶段保持可构建、可独立回退 |
| 新资产量过大拖慢主线 | 先完成公共几何语法和代表资产，按页面清单复用并补齐变体 |
| 设备缺失或工具链阻塞被误写成验收通过 | 记录实际限制，区分源码完成、构建完成和设备验证 |
| 与现有工作区修改交叠 | 实施前确认变更边界，按具体差异修改；保留已有未提交工作，避免整文件覆盖与批量还原 |

## 13. 交付清单与下一步

最终交付应包含：

- 品牌手册：风格文字、配色、几何构成、材质、图标、排版与动效规则。

- 可交互组件样板、新版页面框架与统一主题实现。
- 逐页重构完成的全 App 呈现层与资产，包括二级页、低频工具、错误、空状态和浮层。
