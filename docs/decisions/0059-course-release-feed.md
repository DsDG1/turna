# ADR 0059 — 内置课程离线打包与发布清单

> 状态：Accepted ｜ 日期：2026-10-30

## 决策

- `tool/publish_course.py` 从内置 manifest 按语言定位课程，只生成待上传的 zip 和 `course-feed.json`；不使用账号凭据、不自动创建远端 Release。
- 内容包根目录与课程根目录同构，当前仅收 JSON，拒绝链接、越界路径和其它文件类型。校验、lint、压缩与哈希使用同一份暂存快照；运行现有 `course_cli`，不另造教学内容校验规则。
- 清单格式为 `turna-course-feed/1`，包含 `language`、`latest` 和最多五个 `history`。每条记录含包内 index 与 expressions 版本、URL、SHA-256、字节数、UTC 发布时间及一句说明。
- 每次发布分配独立 index 版本：有基线时必须恰好是上一份清单版本加一；`--bump` 在尚未手动升版时补上，已升到目标版本时不重复加。没有基线时允许生成当前版本的首份清单，或用 `--bump` 生成下一版。expressions 版本照包内值记录，运行时仍按 [ADR 0058](./0058-builtin-course-content-source.md) 的复合版本比较。
- 默认基线是输出目录中上一份生成的 feed；可通过 `--previous-feed` 指定已部署清单。脚本不会把本地打包成功当作远端已发布，也不会凭空推断云端版本。
- `latest.url` 允许相对文件路径，下载器须相对 feed 请求地址解析；它适用于同目录静态托管和局域网。`--base-url` 可生成 HTTPS 绝对地址，Release 附件须使用其实际下载目录。HTTP 只在显式允许且目标为回环／私网时接受；URL 不接受账号密码、查询参数或片段。
- 版本化 zip 不允许被不同内容覆盖。同内容孤儿包可复用，以恢复「zip 已落地、feed 未提交」的中断。zip 完成后才提交源文件升版，最后原子替换 feed；失败时保留旧 feed，源文件仍是本次写入值时回退版本。

## 理由

发布物必须能被现有读取接缝直接消费，因此不引入新的课程容器或内容模型。单独的 index 发布号让每次发布有唯一的包名，也覆盖只改词汇、语法或表达的更新。

只校验源目录后再从源目录打包，会把作者在两个阶段之间的编辑带进未经校验的包。固定快照、打包前复查源文件，能让校验结果和实际上传物保持一致。

feed 是设备发现更新的入口。先上传 zip，再更新稳定地址的 feed，可以避免设备看见尚未上传完整的包。SHA-256 与大小必须从实际 zip 生成，人工填写会产生错配。

## 边界

- 本地 feed 是已准备版本的记录，不等于云端发布记录。输出目录被清理或更换机器时，作者需要提供已部署 feed 作为基线；脚本不联网猜测最近版本。
- 无论相对还是绝对 URL，下载器都须在解析后执行传输协议与目标检查；清单不提供放宽 app 下载策略的权限。
- 清单签名、灰度、远端上传、CI 发布和 app 内回滚属于后续分发能力。
