# ADR 0072 — Phase Two 作者契约与发布边界

> 状态：已接受 ｜ 日期：2026-11-07
>
> 衔接：ADR 0058、0059、0061、0064、0070、0071。

## 背景

课程 JSON、Dart 模型、Python 校验、GUI 和作者文档曾分别描述部分字段，旧 `correctAnswer` 示例因而能通过 Python 校验并在运行时退化为占位卡。教师向导和 AI 提示也仍在生成一词一个三题子课，和独立子课的 12–15 题契约冲突。媒体、定稿和 OTA 版本则容易被误解为一个发布动作。

## 决策

1. **所有题型都过结构校验**：CLI 在普通 stage、子课和听力阶段使用同一逐题型入口，检查必填字段、类型、选项和答案索引。authoring 可执行模板与内嵌 JSON 都进回归。
2. **Phase Two 只有一份共享配方**：`tool/course_pedagogy.py` 定义子课体量、新词间隔、产出、答案位置、CEFR 约束和复习池参数；CLI、GUI 质量报告、教师生成器及 AI 提示共同消费。
3. **作者侧分散答案位置**：生成器确定性重排选项并重算索引；不在运行时临时改变已发布题目的选项顺序。
4. **资源带有教学元数据**：词汇和表达可声明 `level`、`introducedInLessonId`、`learningGoal=recognition|production`。首次教学与后续复现必须可由质量报告追踪。
5. **替代答案是确定性数据**：翻译、阅读简答和拼句使用 `acceptedAnswers`。规范答案负责展示；判分只使用统一规范化，不调用运行时 LLM。拼句替代项仍须使用同一组词块。
6. **阅读词形显式映射**：`readingPassage.wordFormMap` 把文中词形映射到 vocab id；不提供通用形态分析器的虚假承诺。插图同时携带 `imageAlt`。
7. **作者工作区自包含**：导出物包含课程目录、实际引用的媒体和 `workspace.json`。媒体路径可从仓库或工作区解析，与进程工作目录无关。
8. **首单元媒体随 app，课程 OTA 仅 JSON**：新增/修改媒体需要 app 发布；不把图片或音频直接塞入现有课程 ZIP。媒体清单记录来源、生成方式和审校状态。
9. **GUI 只定稿，不分配对外 OTA 版本**：定稿保存、校验、生成报告；`publish_course.py` 以已部署 feed 为基线分配 index 发布号。网页审阅链接与上线是不同动作。
10. **真实验收不可由工具替代**：音频生成/试听、语言审校、移动真机、教师实测和线上状态没有真实证据时均保持未完成。

## 理由

统一结构契约能阻止占位卡进入课程；共享教学配方避免不同生产入口批量制造返工。作者侧固定选项映射保留内容可复现性。显式资源元数据和词形映射比猜测词形更可审校。

版本号若由每次 GUI 保存推进，会与远端 feed 的连续发布号脱节，因此定稿与上线必须分离。首单元媒体量有限，沿用 app 打包比仓促扩展二进制 OTA 更简单，也更易恢复。

## 边界

- 不批量生成第 2–8 章，不为 expressions/grammar 数字制造无教学用途条目。
- 不修改已发布 ID；显示名称与稳定 ID 分开处理。
- 跟读仍是词面可懂度，默认关闭并有平台降级，不是音素级评分。
- SHA-256 只校验下载完整性，不等同于发布者签名；生产信任与签名需要独立的凭据和托管配置。
- 首单元在真实音频、人工语言审校和真机试学完成前仅为候选内容。
