# ADR 0060 — 教材/教学纲领适配与 TTS 参数对齐当前模型

> 状态：Accepted ｜ 日期：2026-10-30

## 决策

- **文档形态先于抽取**：导入管线的入口改为 `markdown_chopper.split_chapters_auto`。除 `#` 标题外，识别 `1.` / `1.2` 编号、`Ünite` / `Bölüm` / `Ders` / `Unit` / `Lesson` / `Chapter` / `第 N 章` / 单元 / 模块与纯加粗行；单个 `#` 书名 + 普通单元阶梯视为「纲领形态」，把普通行提升为 `##` 后再切。编号只有从 `1` 起且同层 ≥2 条才算章标题。
- **文档类型用本地启发式判定，AI 只做可选复核**：`document_profile.profile_document` 用关键词权重 + 结构信号（列表密度、说话人行、长段落、单元阶梯）输出 `kind / preset / confidence / evidence`；置信度 ≥0.45 且教师未手动选过预设时自动切换预设，手动选择不被覆盖。AI 复核失败回落启发式，不阻塞载入。
- **纲领是一种独立预设，不是「另一种教材」**：`textbook_presets` 增加 `document_kind` 与 `prompt_addendum` 字段与 `syllabus` 预设，追加规则注入 `knowledge_prompt` 的规则块（不改 JSON schema）：只抽纲领点名的内容，没有目标语词形就跳过而不是编造，语法主题无例句也建语法点。
- **纲领的主路径是课程规划，不是逐章抽词**：`syllabus_brief` 把纲领解析成 `CoursePlanSpec` 取值（主题、等级范围、章节数、课时、词预算、can-do、约束），规划窗口新增「载入教学纲领…」。单元数是权威——模型给出的 `section_count` 与单元列表不一致时以单元列表为准；纲领的单元顺序原样进入 `constraints`。
- **TTS 参数按官方 `t2a_v2` 对齐**：`generate_audio` 增加 `language_boost`（默认按课程 `index.json` 语言推导，`tr → Turkish`，未知用 `auto`）、`text_normalization_mode`（默认 `quality`）、`emotion`、`sample_rate` / `bitrate`，并维护官方模型白名单（`speech-2.8-*` 为默认，`2.6` / `02` / `01` 仍可用）。未知模型只告警不拒绝（代理别名），未知 `language_boost` 直接拒绝。
- **AI 模型名与 App 侧同源**：GUI 预设改为 DeepSeek（`deepseek-v4.1-flash` / `deepseek-v4.1-pro`）与 MiMo（`mimo-v2.6-pro` / `mimo-v2.6`）+ 自定义；已下线厂商与旧模型 id 作为迁移表存在（转 `custom` 并保留 Base URL，模型 id 改写为当前名）。

## 理由

土耳其语教材在真实项目里很少是规范 Markdown：Word/PDF 转文本后标题变成编号或 `Ünite 1`，整本只有一行 `#` 书名。按固定 `##` 切章会得到 1 章（或 0 章），后面所有抽取参数都失去意义——这是「导入很慢但结果很少」最常见的根因。形态识别必须发生在抽取之前，且不能依赖网络，否则载入会被卡住。

纲领与教材的差别不在长度而在**信息类型**：纲领给顺序、等级、课时与目标，教材给语料。用同一套「抽词」策略处理纲领，模型只能编造目标语词形。把纲领拆成两条路径——逐章抽知识点（供审校）与课程骨架规划（供设计）——比让一个 prompt 同时干两件事更可控，也复用已有的 `CoursePlanSpec` 校验与导入链路。

`language_boost` 是土耳其语 TTS 的正确性开关：不给它，MiniMax 用音色母语的音素系统读 `ı/ş/ğ/ü`，生成的是「听起来像土耳其语」但发音错误的音频，而这类错误在批量生成后几乎不可能人工发现。同理，`text_normalization_mode=quality` 决定数字、日期、缩写是否读成词而不是符号。

模型名硬编码在客户端是腐坏点：App 侧已迁移到 v4.1 / v2.6，GUI 仍写 v4.0 会让两个编辑器对同一账号给出不同的默认配置。迁移表而非枚举兜底，是为了不让「旧 provider + 新 Base URL」这种必然连不通的组合静默出现。

## 边界

- 启发式识别只覆盖「文档类型」与「教学计划取值」，不做 OCR、不做语言自动检测、不判断教材质量。
- 自动切换预设只影响**抽取参数**；教师手动选择的预设永远优先，且没有任何路径会自动改课程内容。
- 纲领解析产出的 `constraints` 是文本约束，不构成对规划器的强制校验；最终仍由 `validate_plan` 与导入前的人工确认把关。
- `prompt_addendum` 只追加规则文本，不改 schema、不改 id 生成、不改合并逻辑。
- TTS 参数升级不改变既有音频产物路径与命名；已生成的 MP3 不会被自动重刷，需要重刷必须显式 `--force`。
- 未知模型 id 仍然放行（代理/固定快照场景），因此「模型名正确性」不由本地校验保证。
