# T.9 零代码教师可用性测试清单

> 目标（guiplan §15.12 / T.9）：找一位**不懂代码**的老师，全程不接触 `id` / `path` /
> `version` / `runtimeType` 等工程概念，独立产出一节合格的「认识新词」(intro) 课，
> 并能自我验证题目对错。本清单是人工执行脚本；自动化回归见
> [`tool/gui/tests/usability_smoke.py`](../../tool/gui/tests/usability_smoke.py)。

## 测试前置

| 条件 | 说明 |
|------|------|
| 测试人 | 1 位不懂 JSON / 编程的语言教师 |
| 环境 | 本机已装 PySide6，能 `python -m tool.gui.src.main` 启动 GUI |
| 记录 | 每步记录：是否需要提示 / 是否暴露工程概念 / 耗时 |

评分标准：步骤全程「无需提示且未暴露工程概念」= 通过；需要提示 = 标记并记录原因。

## 任务路径

### 第 1 步：新建一个课程
- [ ] 点工具栏「新建课程目录」
- [ ] 选一个空目录，填课程显示名（如「我的英语课」）
- [ ] 点「初始化」
- [ ] **通过标准**：左侧出现课程树，无需输入任何 `id` / `language` 代码
- [ ] **检查**：老师是否被要求填写 `version` / `language` 字段？（应为否）

### 第 2 步：用向导建一节「认识新词」课
- [ ] 切到「教师模式」
- [ ] 点「向导建课」
- [ ] 课型选「认识新词」，填名称「问候语」
- [ ] 从词库勾选 3 个词
- [ ] 点「生成课程」
- [ ] **通过标准**：右侧出现 3 个教学环节，每个环节含「展示→翻译→填空」3 道题
- [ ] **检查**：老师是否看到 `runtimeType` / `wordId` / `correctIndex` 字样？（应为否，应只看到「展示生词 / 翻译题 / 填空题」与词面）

### 第 3 步：逐题微调
- [ ] 点开一道「选择题」，点选项前的圆圈改正确答案
- [ ] 用「↑/↓」移动一道题的顺序
- [ ] 用「🗑️」删除一道题（弹出确认）
- [ ] **通过标准**：所有操作有图形入口，无需改 JSON
- [ ] **检查**：移动/删除后选中与展开状态是否保留？（A1 要求）

### 第 4 步：预览试做
- [ ] 点「🔍 预览本课」
- [ ] 实际做一遍每道题，点「提交」看对错
- [ ] **通过标准**：能像学生一样做题并即时看到 ✅/❌
- [ ] **检查**：改一道题后重新打开预览，内容是否刷新？

### 第 5 步：保存
- [ ] 点「保存」
- [ ] **通过标准**：状态栏提示保存成功；标题栏无 `*`
- [ ] **检查**：若故意制造错误（如删掉一个词再让题目引用它），保存是否回滚并在校验报告里用人话指出错误？（A2 要求）

### 第 6 步：撤销误操作
- [ ] 误删一道题后按 Ctrl+Z
- [ ] **通过标准**：题目恢复；再 Ctrl+Y 可重做
- [ ] **检查**：撤销栈是否清晰可预期？

### 第 7 步：发布
- [ ] 点「发布」
- [ ] **通过标准**：看到「本次改动 / 自动版本号 / 校验通过 / 点发布」的人话清单
- [ ] **检查**：老师是否需要手动改 `version`？（应为否，C3/发布流程要求）

## AI 增强路径（可选进阶）

> 在已完成基础建课流程后，可测试教师是否能**不接触 JSON / 模型配置 / ID 等工程概念**，
> 仅通过 GUI 完成 AI 生成课程、预览、导入、修正与用量查看。
> 自动化回归见 [`tool/gui/tests/usability_smoke.py`](../../tool/gui/tests/usability_smoke.py)。

### 第 A1 步：配置 AI（建议由测试员预填 API Key）
- [ ] 打开工具栏「设置 → AI 配置」
- [ ] 选择供应商预设（DeepSeek / OpenAI / Moonshot / Ollama）
- [ ] 点击「测试连接」看到成功提示
- [ ] **通过标准**：教师只须选择预设并（在测试员未预填时）填入 API Key，无需手动输入 Base URL 或模型名
- [ ] **检查**：是否暴露 `base_url` / `model` / `reasoning` 等工程字段？（预填情况下应为否）

### 第 A2 步：在课程工坊生成一节「认识新词」课
- [ ] 打开「课程工坊」→ 项目库点「空白 AI 项目」（进入创意画布）
- [ ] 中间 AI 轨道：模板选「认识新词」，等级/单元/课时按需调整
- [ ] 在「主题」填写「问候语」
- [ ] 点击圆形「AI 核心」或按 Ctrl+Enter
- [ ] **通过标准**：底栏有阶段标签与 token/估算成本；生成后自动切到右栏「结构大纲」
- [ ] **检查**：教师是否被要求直接编辑 JSON？（核心路径应为否，看结构大纲即可）

### 第 A3 步：试做与导入
- [ ] 在右栏「结构大纲」点「试做」，选一课时做一遍题
- [ ] 关闭预览，点「导入到课程 ↗」
- [ ] 若弹出「切换教师模式并定位」，可任选；然后主窗口「保存」
- [ ] **通过标准**：能像学生一样验证题目，导入后左侧课程树出现新 unit/lesson
- [ ] **检查**：导入内容是否与预览一致？

### 第 A4 步：用许愿聊天 + 附件生成听力课
- [ ] 中间点「打开对话 / 附件 / 模板…」进入「设计与草稿」
- [ ] 聊天框输入「帮我生成一节餐厅对话的听力课」
- [ ] 点「附件」或拖入 PDF / Word / 文本，点 chip 确认提取内容
- [ ] 多轮对话磨合后，点生成（轨道核心或设计页「生成课程 ▶」）
- [ ] **通过标准**：可不打开 JSON 完成磨合与导入
- [ ] **检查**：附件预览是否帮助确认材料内容？

### 第 A5 步：错误处理与 diff
- [ ] 在教师视图中故意制造一个 AI 可修正的问题（如引用缺失的词）
- [ ] 选择「AI 自动修正」并等待结果
- [ ] 修正完成后点击「查看 diff」，看清改动
- [ ] 确认无误后点「应用」
- [ ] **通过标准**：教师能看清 AI 改了什么，再决定是否接受
- [ ] **检查**：是否暴露原始 JSON diff 之外的工程概念？（应为否）

### 第 A6 步：查看用量
- [ ] 打开「设置 → AI 用量」
- [ ] **通过标准**：教师能看到今日/累计 token、请求数、估算成本与成功率
- [ ] **检查**：界面是否明确标注「估算 / 不作为计费依据」？
