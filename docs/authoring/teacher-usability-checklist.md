# 教师可用性检查清单（人工验收）

> 面向**零代码语言老师**的人工走查清单。每轮 GUI 重大改动后，由一位**没参与开发**的
> 老师按本清单走一遍。
>
> 自动化回归见 [`tool/gui/tests/usability_smoke.py`](../../tool/gui/tests/usability_smoke.py)
> （它只覆盖「建课 → 校验 → 预览 → 发布清单」这条机器可判定的路径；本清单覆盖
> 自动化测不到的部分：**文案是否看得懂、步骤是否找得到、失败时是否有出路**）。

---

## 使用方法

1. 找一位**没用过这个工具**的老师（开发者自己走不算数）。
2. 全程**不要提示**。老师卡住超过 2 分钟才算「找不到路」。
3. 走完一节勾一行；卡住的写清楚**卡在哪一步、当时以为发生了什么**。
4. 一轮至少 3 位老师；同一处被 2 人以上卡住 = 必须修。

---

## 一、开箱（首次启动）

- [ ] 双击程序能打开，无报错弹窗
- [ ] 打开后**第一眼知道下一步做什么**（不用问「我现在该干嘛」）
- [ ] 「打开课程」入口一眼能找到
- [ ] 没打开课程时，其他入口是禁用/灰的，而不是点了才报错

---

## 二、建课主路径

- [ ] 能从零建出一节「认识新词」(intro) 课：词 → 课 → 保存
- [ ] 每一步都有**明确的下一步提示**（按钮文案说的是动作，不是名词）
- [ ] 校验报错时，能看懂**错在哪、怎么改**
- [ ] 报错文案里说的是**老师的语言**（不是「schema mismatch」「field required」）

---

## 三、编辑与撤销

- [ ] 能改一个字段并保存
- [ ] 能撤销上一步（**且知道怎么撤销**：有快捷键或菜单项）
- [ ] 误删了东西**能救回来**
- [ ] 改坏了**知道怎么回退**（不依赖「重开程序」）

---

## 四、失败路径（**最重要的一节**）

自动化测不了这三条，但它们决定老师会不会放弃这个工具。

- [ ] 断网时点 AI 功能：**明确告知**网络问题，不是转圈卡死
- [ ] AI 返回看不懂的内容：**有可见的失败提示**，不是静默无反应
- [ ] 保存失败：**课程内容不丢**，且明确告知「没保存上」
- [ ] 课程文件被外部改坏：打开时**给出可读的错误**，不是空白页

---

## 五、体面收场

- [ ] 关窗时如果有未保存内容：**会问**，且选项说得清（保存 / 不保存 / 取消）
- [ ] 关窗等待保存时**窗口不假死**（有进度或至少不卡死鼠标）
- [ ] 关闭耗时在**大课程**上也感觉不到卡顿（< 2 秒）
- [ ] 关掉再打开，**上次的位置还在**（展开的节点、选中的课）

---

## 六、长期使用（连用 2 小时以上）

- [ ] 连续用 2 小时，**内存没有明显膨胀**（任务管理器看）
- [ ] 课程树来回滚动/点击，**不卡顿**
- [ ] 日志/操作记录文件**没有涨到撑爆磁盘**（看 `~/.turna-gui/`）
- [ ] 切换主题后，图标/高亮/阴影**都跟着变**（不是只变了一半）

## 与自动化门禁的关系

本清单**不替代**门禁。门禁守结构（分层、ratchet、测试），
本清单守**体验**——两者互补，缺一不可。

发现的问题按性质分流：

- **功能坏了** → 补自动化测试 + 修代码
- **文案/路径找不到** → 改 UI，不一定要补测试
- **卡顿/资源泄漏** → 补性能回归（见 `tool/gui/tests/test_experience_perf.py` 等）
